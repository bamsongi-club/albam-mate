# HTTP 기능 테스트 매트릭스

기능 정본과 API 계약을 먼저 읽고, 해당하는 항목만 고른다. 이 문서는 제품 정본이 아니라 누락 방지용 실행 체크리스트다.

- `issue-writer`는 feature·bug 이슈의 적용 항목을 `T1: 비로그인 요청은 401을 반환한다.`처럼 관찰 가능한 한 줄로 제안한다.
  - 후보를 승인·확정하거나 이슈 본문에 넣지 않는다.
  - 사람이 GitHub Issue 코멘트로 확정한 최신 전체 목록만 필수 테스트 계약의 정본이다.
- `backend-delivery`는 적용 항목을 패킷의 완료 기준과 대상 테스트에 넣는다.

| 범주 | 확인할 항목 |
| --- | --- |
| 경로·메서드 | 정의된 method/path만 노출되고, 대상 ID·하위 경로가 없는 계약에 다른 사용자 경로를 추가하지 않는다. |
| 인증·인가 | 비로그인, 잘못된 인증 상태, 현재 사용자와 다른 대상에 대한 접근 경계를 검증한다. |
| CSRF | 상태 변경 경로의 유효·누락·잘못된 토큰을 각각 계약 오류 코드로 검증한다. |
| 세션·쿠키 | 인증 상태 변경은 실제 HTTP 서버와 쿠키 저장소로 한 흐름에서 검증한다: `Set-Cookie` 속성, 로그인 후 보호 API 성공, 로그아웃 후 기존 쿠키 거절. `MockHttpSession` 직접 주입만으로 브라우저 쿠키 재전송·만료 계약을 완료로 보지 않는다. |
| 입력 | 누락, null, 빈 객체, 빈 문자열, 공백 정규화, 최솟값·최댓값·초과값, 제어문자를 계약에 맞게 검증한다. |
| Unicode | 계약이 문자 수를 말하면 UTF-16 length 대신 code point 기준의 BMP·보조 평면 경계를 검증한다. |
| 응답 | HTTP status와 봉투 status를 함께 확인하고, DTO 외 Entity·비밀번호·세션·인증 정보가 노출되지 않는지 확인한다. |
| 상태 변경 | 성공 응답, 영속 반영, 후속 조회, 실패 시 서비스·저장소 미호출 또는 상태 불변을 검증한다. |
