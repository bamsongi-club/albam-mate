# 백엔드 전달 절차

## 진입

- PR 피드백은 `gh-address-comments`로 현재 head와 미해결 스레드를 확인하고, 사용자가 선택한 유효한 수정만 정본과 대조한다.
- 이슈 구현은 사람이 승인한 최신 전체 테스트 계약과 현재 정본을 대조한다.
- 모호·상충하거나 설명만 필요한 코멘트는 구현하지 않는다. 명시적 요청 없이 답글을 게시하거나 스레드를 해결하지 않는다.

## 모드 선택

- 다음 조건을 모두 만족하면 [review-fast](references/review-fast.md)만 읽고 따른다.
  - 사용자가 승인된 이슈 구현이나 기존 open PR의 미해결 리뷰 수정을 명시했다.
  - 승인된 이슈·PR 계약 밖으로 관찰 가능한 동작과 테스트 의도를 바꾸지 않는다.
  - 한 동작 영역의 직접 관련 경로와 대상 테스트를 식별할 수 있다.
  - 인증·인가·CSRF·개인정보·공개 API, DB 마이그레이션·스키마·데이터 보정, 트랜잭션·동시성, 모듈 경계, 의존성·빌드·운영 설정을 바꾸지 않는다.
- 그 외에는 [full-delivery](references/full-delivery.md)를 읽고 따른다. 테스트 실행을 독립 tester에게 맡길 때만 [결정적 테스트 runner](references/test-contract-harness.md)를 추가로 읽는다. 리뷰 심각도와 변경 줄 수만으로 모드를 정하지 않으며, 진행 중 범위가 넓어지면 다시 분류한다.

## 공통 전달 경계

- 커밋·푸시·PR 요청이면 `pr-writer`를 사용하고, 사용자가 승인한 작업 범위의 파일만 명시 경로로 스테이징한다.
- 변경 경로의 staged·unstaged·untracked 내용을 확인하고 `git diff --check`를 실행한다. 실행 중인 명령은 종료 상태를 확인할 때까지 다시 시작하지 않는다.
- 로컬·upstream·원격 SHA와 worktree 상태를 확인하되 깨끗한 worktree를 요구하거나 관련 없는 staged·unstaged·untracked 변경을 정리하지 않는다.
- 사용자가 CI 통과까지 요청했거나 완료 기준이 CI를 요구할 때만 원격 CI 완료를 기다린다. 그 외에는 PR 생성 사실과 현재 CI 상태를 구분해 보고한다.
