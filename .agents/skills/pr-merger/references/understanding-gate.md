# Diff 이해도 게이트

## 출제

- 실제 diff와 검증 결과를 읽고 외부 동작과 실패 영향의 최고 위험도에 따라 한 번에 출제한다.
  - 1문항: 문서·템플릿·주석만 바뀌고 실행 동작·배포·필수 CI에 영향이 없다.
  - 2문항: 영향이 제한된 일반 애플리케이션·자동화·설정 변경이며 고위험 조건이 없다.
  - 3문항: 인증·인가·보안·개인정보, 동시 상태 변경, DB 스키마·마이그레이션·데이터 손실, 비밀정보, 배포·필수 CI, 하위 호환성이 깨지는 공개 API에 해당한다.
- 선택한 문항 수와 근거를 내부 기록한다.
- 변경 목적·동작·계약·실패·검증 중 위험과 연결된 개념만 묻는다. 실제 사용 상황과 선행 상태를 제시하고 외부에서 관찰되는 결과를 고르게 하며, 구현 암기·중복·추측·함정은 피한다.
- 각 문항은 A~D 중 하나만 정답으로 두고 위치를 섞는다. 오답은 diff와 명확히 모순되게 만들되, 길이·상세함·구조 같은 형식 단서로 정답이 드러나지 않도록 선택지를 대칭적으로 구성하고 제출 전에 확인한다.

## 제출과 채점

- 사용자에게 문항 수만큼 답을 직접 제출해 달라고만 요청하고 응답 예시·내부 검사·정답 암시는 공개하지 않는다.
- 답변을 받으면 각 문항의 정오와 실제 diff 근거를 짧게 설명한다.
- 맞힌 개념은 이월하고, 틀린 개념만 설명한 뒤 다른 실제 상황으로 한 차례만 재시험한다.
- 재시험에서도 같은 개념을 틀리면 세 번째 퀴즈를 내지 않는다. 해당 diff의 목적, 외부 동작, 실패 영향과 검증 결과를 `변경 요약`으로 짧게 설명하고, 사용자가 설명을 이해했으며 고정한 스냅샷 HEAD의 머지 진행에 동의한다고 명시하도록 요청한다.
- 선택한 모든 개념을 퀴즈로 맞히거나 재시험 후 변경 요약을 이해하고 머지에 명시적으로 동의하면 이해도 게이트를 통과한다.
- 사용자 대신 답하거나 변경 요약을 제공하지 않은 단순 확인으로 통과시키지 않는다.
- 원래의 명시적 머지 요청은 답변을 기다리는 pending 요청으로 유지한다. 이해도 게이트를 통과하면 별도 재확인 없이 남은 머지·삭제를 계속한다.
- PR 번호, 제목, `baseRefOid`, `headRefOid`, diff, 리뷰, CI 상태가 달라지면 기존 정답 이월과 변경 요약 확인을 모두 무효화한다.
