# Issue Writer

## 경계와 정본

- `templates.json`의 `enabled: true` 항목만 후보로 삼고 `intent`로 분류한다. 필드·순서·필수 여부는 각 항목이 가리키는 `.github/ISSUE_TEMPLATE/*.yml`이 정본이다.
- 시작 시 `node .agents/skills/issue-writer/scripts/validate-template-registry.mjs`를 실행한다. 실패하거나 맞는 Form이 없으면 선택·게시하지 않는다.
- 작성·초안 요청은 초안만 제공하고, 올리기·게시·만들기처럼 게시 의도가 명확할 때만 이슈를 생성한다. 코드·커밋·PR은 만들지 않는다.
- 저장소에서 확인된 사실만 Form에 채우고 미확정 사항은 `결정 필요`로 남긴다. 정본은 복제하지 않고 링크하며, 확인하지 않은 상태를 완료로 표시하지 않는다.
- feature·bug 이슈는 관찰 가능한 자연어 테스트 후보를 `T1`부터 본문과 분리해 제안한다. 후보는 사람 승인 전 상태이며, 사람이 이슈 코멘트로 승인한 최신 전체 목록만 필수 테스트 계약의 정본이다. HTTP 경계는 [HTTP 기능 테스트 매트릭스](../../references/http-feature-test-matrix.md)로 확인한다.
- 초안에는 선택한 템플릿 ID·제목·본문과, 해당하면 T-ID 후보를 제시한다. 분류나 필수 내용이 모호하면 필요한 결정 하나만 묻고 blank issue로 우회하지 않는다.

## 게시 절차

1. 인증과 정확한 저장소를 확인한다.
2. `state=all` 전체 이슈를 끝까지 조회하고 PR을 제외해 목적·기능 ID·소유 경로가 같은 중복을 확인한다. 중복이면 새로 만들지 않고 기존 이슈를 제시한다.
3. 제목·본문·라벨을 Form과 저장소에 대조한 뒤 게시한다.
4. 생성된 이슈를 번호로 다시 조회해 제목·본문을 검증하고, 템플릿·번호·URL과 사람 승인이 필요한 T-ID 후보를 보고한다.
