# semantic-30 제3 판정자 검수 안내

아래 안내와 [`semantic-30-judge-c-worklist.json`](semantic-30-judge-c-worklist.json)을 독립 제3 판정자에게 전달합니다.

## 그대로 전달할 문구

안녕하세요. 검색 품질 평가에서 A/B 두 판정자의 점수가 달랐던 후보만 제3 판정을 부탁드립니다.

이번 작업은 게임 자체의 재미나 품질을 평가하는 것이 아니라, **질의 문장에 이 게임이 얼마나 잘 맞는지**를 판단하는 작업입니다. 총 30개 질의, 585개 후보가 있으며, 각 후보의 `evidenceText`에 있는 게임 정보만 보고 판단해 주세요.

판정은 다른 사람의 결과와 맞추는 것이 아니라 독립적으로 진행해야 합니다. A 판정, B 판정, 기존 C 추론값과 검색 모델 점수는 보지 말아 주세요. 파일의 `blindRank`는 표시 순서일 뿐이므로 판단 근거로 사용하지 마세요. 외부 검색으로 게임 정보를 보충하지 말고 파일에 제공된 정보만 사용해 주세요.

### 점수 기준

- `2점`: 질의의 핵심 플레이 경험이 게임의 주된 방식이고, 질의에 인원·시간 조건이 있으면 그 조건도 모두 충족합니다.
- `1점`: 질의와 관련된 요소는 있지만 핵심 경험이 부차적이거나 일부만 맞습니다. 조건형 질의에서 인원·시간 정보가 불완전한 경우도 여기에 해당합니다.
- `0점`: 질의의 핵심 경험과 직접 관련이 없거나, 조건형 질의의 필수 인원·시간 조건을 명확히 만족하지 않습니다.

각 질의의 세부 기준은 파일의 `judgementRubric`을 우선해 주세요. 예를 들어 단순히 `파티`, `추리`, `협력`이라는 분류가 있다는 이유만으로 2점을 주지 말고, 질의가 말하는 핵심 경험이 실제 설명의 중심인지 확인해 주세요.

### 입력 방법

1. `semantic-30-judge-c-worklist.json`을 엽니다. 이 파일에는 이번에 판정할 585개 후보만 들어 있습니다.
2. 각 질의의 `query`와 `judgementRubric`을 먼저 읽습니다.
3. 해당 후보의 `evidenceText`를 읽고 `grade`에 `0`, `1`, `2` 중 하나를 입력합니다.
4. `rationale`에는 왜 그 점수를 줬는지 한 문장으로 적습니다. 제공된 게임 설명에 근거해 작성해 주세요.
5. 585개 모든 후보의 `grade`와 `rationale`을 채웁니다. 모르는 후보도 비워 두지 말고, 제공된 정보 기준으로 가장 가까운 점수를 선택한 뒤 불확실한 이유를 근거에 적습니다.

### 파일 수정 규칙

- 수정할 수 있는 값은 각 후보의 `grade`와 `rationale`뿐입니다.
- `id`, `query`, `blindRank`, `gameId`, `evidenceText`와 쿼리 정보는 수정·삭제·정렬 변경하지 않습니다.
- `grade`는 반드시 숫자 `0`, `1`, `2` 중 하나로 입력합니다.
- `rationale`은 빈 문자열이나 `null`로 두지 않습니다.
- A/B 결과를 추측해 맞추거나 평균 점수를 쓰지 않습니다.
- 한 번에 부담되면 100건씩 다섯 번 + 마지막 85건으로 나눠 검수해도 되지만, 동일한 기준을 유지합니다.

### 완료 후 확인

파일을 돌려줄 때 다음을 함께 알려 주세요.

```text
제3 판정 완료
- 판정 파일: semantic-30-judge-c-worklist.json
- 입력 완료: 585/585
- 미입력 grade/rationale: 0
- grade 허용 범위 위반: 0
- 후보·질의 정보 수정: 없음
```

반환된 파일은 담당자가 canonical packet에 반영한 뒤, A/B와 제3 판정의 다수결로 최종 qrels를 다시 생성합니다. 이 worklist 자체는 최종 qrels 파일이 아니므로, 판정자는 별도의 qrels·metrics 파일을 만들지 않습니다.

## 담당자 확인 사항

판정 파일을 받은 뒤 다음을 확인합니다.

- 30개 질의의 대상 수 합계가 585개인지
- 모든 대상의 `grade`가 0·1·2 중 하나인지
- 모든 대상의 `rationale`이 비어 있지 않은지
- `gameId`와 `evidenceText`가 전달 전과 같은지
- A/B 파일이나 기존 추론 C 값이 판정자에게 노출되지 않았는지

검증이 끝난 뒤에만 제3 판정 결과를 `semantic-30-judge-c.json`에 병합하고 approved qrels와 metrics를 재생성합니다.
