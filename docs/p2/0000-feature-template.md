## 구현 컨텍스트

### 해결할 사용자 문제

누가 어떤 상황에서 무엇 때문에 막히며, 이 기능으로 어떤 최종 결과를 얻는지 적는다. 기술 도입 자체를 문제로 쓰지 않는다.

### 핵심 사용자 흐름

~~~text
시작 조건
→ 사용자 입력·행동
→ 서버의 권한·업무 검증
→ 성공 결과
→ 사용자가 확인하는 최종 상태
~~~

업무 거절, 기술 실패, timeout·재시도와 복구 흐름도 별도로 적는다.

## 기능 규칙

### 데이터

- 입력·출력 데이터의 출처, 소유자와 이용 근거
- 저장·색인·가공·보존·삭제·마스킹 기준
- 개인정보·비밀값·원문을 메트릭 label이나 중앙 로그에 넣지 않는 경계

### 인증·권한

- 사용자 역할과 접근 조건
- 기존 인증·인가·CSRF·업무 불변식을 통과하는 호출 경계
- Tool Calling이나 내부 호출이 사용자 권한을 우회하지 않는 방법

### 상태·동시성·일관성

- 상태와 전이 소유자
- 중복 요청·재시도·idempotency·순서 역전 처리
- 트랜잭션, 잠금, 이벤트와 최종 일관성 경계

### 실패·복구

- 업무 거절과 기술 실패의 오류 계약
- timeout, 외부 의존성 실패, 부분 성공과 fallback
- 재시도·보상·수동 복구·운영자 개입 조건

## 완료 기준
