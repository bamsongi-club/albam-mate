# P1 인기 랭킹 기능 명세

이 문서는 P1 조건부 후속에서 채택한 `RANK-01`의 구현 규칙과 완료 기준을 정의한다. 현재 계약·생산 코드·자동 검증·운영 상태는 [P1 기능 상태 정본](README.md#기능별-현재-상태)을 따른다.

전체 범위와 공통 규칙은 [P1 명세](../P1-spec.md), 요청·응답·오류는 [API 명세](../API.md), 저장 구조와 제약은 [ERD](../ERD.md)를 따른다. `RANK-01`은 기존 `ROOMS`와 `GAMES`의 필드만 사용하므로 신규 저장 계약, 전진 Flyway 마이그레이션과 ERD 변경을 요구하지 않는다.

`RANK-01`은 2026-08-11 [#596](https://github.com/bamsongi-club/albam-mate/issues/596)에서 P1 필수 범위로 채택됐다. 승인된 결정이 바뀌면 후속 이슈나 ADR로 기존 결정을 대체하고 이 문서를 함께 갱신한다.

## RANK-01 인기 게임 랭킹

밤송이 내부 방 데이터만으로 게임별 모임 수를 세어 `전체`와 `지난 7일` 두 랭킹을 제공한다. 외부 사이트 점수, 개인화와 검색 이벤트는 사용하지 않는다.

### 기능 규칙

- 응답 필드 이름·타입과 오류는 [인기 게임 랭킹 조회 API](../API.md#rank-01-인기-게임-랭킹-조회)가 정본이다. 이 절은 집계의 의미와 판정 규칙만 정의한다.
- 랭킹은 게임 목록과 같이 비로그인도 조회한다. 요청자에 따라 결과가 달라지지 않으므로 세션 유무로 값을 바꾸지 않는다.
- 집계 대상은 `roomType`이 `GAME_FOCUSED`이고 `status`가 `CANCELED`가 아닌 방이다. `PERSON_FOCUSED`는 특정 게임의 모임이 아니므로 세지 않고, 취소된 방은 열리지 않았으므로 어느 랭킹에도 넣지 않는다.
- `RECRUITING`, `CLOSED`, `FINISHED`는 모두 집계한다. 인기는 모임의 성사 결과가 아니라 그 게임으로 모임이 열린 횟수로 판정한다.
- 한 요청은 `requestTime` 하나를 고정하고 두 랭킹에 같은 값을 사용한다. 랭킹마다 현재 시각을 다시 읽지 않는다.
- `전체`는 기간 조건을 적용하지 않고 집계 대상 방을 모두 센다.
- `지난 7일`은 `Room.startAt`이 `[requestTime - 7일, requestTime)`인 방만 센다. 시작 경계는 포함하고 종료 경계(기준 시각)는 제외한다. 아직 시작하지 않은 방은 이 랭킹에 넣지 않는다.
- 두 랭킹 모두 집계 모임 수 내림차순, 같은 수에서는 게임 ID 오름차순으로 정렬한다. 이 정렬은 같은 데이터에서 항상 같은 순서를 만든다.
- 각 랭킹은 정렬한 뒤 상위 10개까지 반환한다. 순위는 1부터 순서대로 부여하며 집계 수가 같아도 같은 순위를 공유하지 않는다.
- 집계 대상 방이 없거나 기간에 해당하는 방이 없으면 오류가 아니라 빈 랭킹을 반환한다. 두 랭킹은 서로 독립적으로 비어 있을 수 있다.
- 응답은 순위, 게임 식별자·표시 정보와 집계 모임 수만 담는다. 방 제목·장소·시각, 주최자·참가자와 사용자 식별 정보를 담지 않는다.
- 게임 표시 정보는 게임 목록·상세가 이미 반환하는 값을 그대로 사용하고 랭킹 전용 표시 필드를 새로 만들지 않는다. 목록이 반환하는 게임명·영문명·출시 연도·대표 이미지와 상세가 반환하는 한 줄 설명이 여기 해당한다.
- `game`은 방 데이터를 직접 읽지 않는다. 필요한 집계는 `game`이 소유한 조회 계약으로 요청하고 `room`이 구현을 제공한다. 컴파일 의존 방향은 기존 `UpcomingRoomCountQuery`와 같이 `room → game.contract`로 유지한다.
- 랭킹 결과를 캐시하거나 별도 집계 테이블·점수 열에 저장하지 않는다. 요청 시점의 조회로 계산한다.

### 권장 조회 구조

- 두 랭킹은 각각 하나의 집계 조회로 얻는다. 방 Entity 전체를 애플리케이션으로 읽어 세지 않는다.
- 정렬과 상위 10개 제한은 집계 조회에 함께 위임한다. 전체 게임의 집계를 받아 애플리케이션에서 자르지 않는다.
- 게임 표시 정보는 집계로 얻은 게임 ID 집합에 대해서만 조회한다. 두 랭킹의 게임 ID를 합쳐 한 번에 조회하고, 조회 결과가 없는 게임 ID는 랭킹에서 제외한다.
- 인덱스는 기능 정확성을 먼저 검증한 뒤 대표 분포의 실행 계획과 측정 결과로 결정한다.

### 완료 기준

- `RANK-01-AC1` 두 랭킹 모두 `GAME_FOCUSED`이고 `CANCELED`가 아닌 방만 게임별로 집계하며, `PERSON_FOCUSED`와 `CANCELED`는 어느 랭킹에도 포함하지 않는다.
- `RANK-01-AC2` `지난 7일` 랭킹은 같은 요청의 고정 `requestTime` 기준 `[requestTime - 7일, requestTime)`에 시작한 방만 집계하고, 시작 경계 포함·종료 경계 제외를 지킨다.
- `RANK-01-AC3` 두 랭킹이 집계 모임 수 내림차순·게임 ID 오름차순으로 정렬되고, 집계 수가 같아도 결과 순서가 안정적이며, 각각 상위 10개까지만 1부터 순서대로 순위를 부여한다.
- `RANK-01-AC4` 공개 조회가 인증 없이 성공하고 순위, 게임 식별자·표시 정보와 집계 모임 수만 반환하며 방·주최자·참가자 정보와 내부 Entity를 노출하지 않는다.
- `RANK-01-AC5` 집계 대상 방이 없거나 기간에 해당하는 방이 없어도 오류가 아닌 빈 랭킹을 반환한다.
- `RANK-01-AC6` `game`이 소유한 조회 계약을 `room`의 조회 구현이 제공해 `game`이 `room`의 Entity·Repository를 직접 참조하지 않는다.
- `RANK-01-AC7` 프론트가 `전체`와 `앞으로 7일`을 구분해 표시하고 로딩·빈 결과·재시도 가능한 오류 상태를 제공하며 각 항목에서 게임 상세로 이동할 수 있다.
- `RANK-01-AC8` 대표 분포의 PostgreSQL 실행 계획을 확인하고, 측정된 병목이 있을 때만 전진 마이그레이션과 [ERD](../ERD.md)에 인덱스를 반영한다.

### 제외 범위

- BGG 해외 순위, 보드라이프 국내 순위와 외부 점수·내부 점수의 결합
- 자유문자 인기 검색어, 검색 이벤트 저장과 검색 기반 인기 지표
- 개인화 랭킹과 사용자별 추천
- 참가자 수, 정원 충족률, 평점과 해 본 게임 표시 수 같은 다른 인기 지표
- 기간·개수·정렬을 요청이 지정하는 파라미터와 페이지네이션
- Redis·별도 검색 엔진·선제 캐시와 운영 근거 없는 선제 인덱스

외부 랭킹과 인기 검색어는 출처·수집·노출 계약을 별도 이슈로 확정한다. 다른 인기 지표가 필요해지면 이 문서의 집계 기준을 바꾸지 않고 새 기능 ID로 분리한다.
