# P0 방 기능 명세

이 문서는 P0 방 기능을 독립적으로 구현·검증할 수 있는 단위로 정의한다. 공통 정원·상태·권한·시간 규칙은 [P0 공통 명세](../P0-spec.md#공통-규칙), 요청·응답·오류는 [API 명세](../API.md), 저장 계약은 [ERD](../ERD.md)를 정본으로 삼는다.

이 문서의 필수 ADR은 모두 승인됨 상태이며, 구현 완료 여부는 각 ADR의 구현 검증 항목에서 별도로 확인한다.

## ROOM-01 방 탐색

### 구현 컨텍스트

| 구분 | 정본 |
| --- | --- |
| API 계약 | [방 목록 조회](../API.md#room-01-방-목록-조회) |
| 공통 규칙 | [방 상태](../P0-spec.md#방-상태roomstatus), [권한과 공개 범위](../P0-spec.md#권한과-공개-범위), [상태 정합성과 동시 변경](../P0-spec.md#상태-정합성과-동시-변경) |
| 데이터 모델 | [ROOMS](../ERD.md#rooms), [GAMES](../ERD.md#games) |
| 필수 ADR | [ADR-0012 요청 경계 방 상태 정합화](../adr/room/0012-room-request-boundary-state-reconciliation.md) |

### 기능 규칙

- 게임 중심 탐색은 선택한 게임의 방을 조회하고, 사람 중심 탐색은 방 제목으로 모임 분위기를 검색한다.
- 두 탐색 방식은 같은 방 데이터를 사용하며 화면의 강조점만 다를 수 있다.
- 검색 조건, 공개 대상, 정렬, 페이지네이션과 응답 필드는 API 계약을 따른다.

### 완료 기준

- `AC1` 게임 중심 조회는 선택한 게임에 해당하는 공개 방만 반환한다.
- `AC2` 사람 중심 조회는 검색어가 있으면 제목 부분 일치 결과를 반환한다.
- `AC3` 상태 정합화가 끝난 현재 공개 대상만 목록에 포함하며 `joinable`은 요청자 기준으로 계산한다.
- `AC4` 비로그인 사용자도 방 목록을 조회할 수 있다.

### 제외 범위

- 게임 인원·시간·복잡도·태그 조건 필터
- 사람 중심 탐색의 지역·경험 수준 조건 필터
- 개인화 추천과 목록 순위 최적화

## ROOM-02 방 상세

### 구현 컨텍스트

| 구분 | 정본 |
| --- | --- |
| API 계약 | [방 상세 조회](../API.md#room-02-방-상세-조회) |
| 공통 규칙 | [권한과 공개 범위](../P0-spec.md#권한과-공개-범위), [방 상태](../P0-spec.md#방-상태roomstatus), [상태 정합성과 동시 변경](../P0-spec.md#상태-정합성과-동시-변경) |
| 데이터 모델 | [ROOMS](../ERD.md#rooms), [GAMES](../ERD.md#games) |
| 필수 ADR | [ADR-0012 요청 경계 방 상태 정합화](../adr/room/0012-room-request-boundary-state-reconciliation.md) |

### 기능 규칙

- 공개 사용자와 방 관계자는 공통 공개 범위에 맞는 서로 다른 상세 응답을 받는다.
- `GAME_FOCUSED` 방은 선택한 게임 정보를 표시한다.
- `PERSON_FOCUSED` 방은 게임을 선택하지 않을 수 있으며, 이 경우 화면에 `게임 미정`으로 표시한다.
- 응답 필드와 `joinable` 계산은 API 계약을 따른다.

### 완료 기준

- `AC1` 비로그인 사용자와 방 관계가 없는 사용자는 공개 범위의 상세만 조회한다.
- `AC2` 주최자와 현재 `ACTIVE` 참가자는 관계자 범위의 상세를 조회한다.
- `AC3` 관계자 응답만으로 요청자가 주최자인지 참가자인지 구분할 수 있어 방 관리와 참가 취소 중 어떤 동작을 제공할지 결정할 수 있다.
- `AC4` 최종 상태 방의 조회 권한과 존재 여부 은닉이 공통 권한 규칙과 일치한다.
- `AC5` 방 유형에 따라 게임 정보 또는 `게임 미정`이 일관되게 표시된다.
- `AC6` 관계자 응답은 API의 캐시 방지 헤더를 반환하며, 참가 취소·로그아웃 뒤 같은 URL에서 이전 정확한 장소와 참가자 정보가 재사용되지 않는다.

### 제외 범위

- 취소한 참가자의 이력 공개
- 사용자 식별자와 연락처 공개
- 방 상세에서 참가 승인·대기열 관리

## ROOM-03 방 생성

### 구현 컨텍스트

| 구분 | 정본 |
| --- | --- |
| API 계약 | [방 생성](../API.md#room-03-방-생성) |
| 공통 규칙 | [정원](../P0-spec.md#정원capacity), [방 상태](../P0-spec.md#방-상태roomstatus), [권한과 공개 범위](../P0-spec.md#권한과-공개-범위), [시간 경계](../P0-spec.md#시간-경계) |
| 데이터 모델 | [ROOMS](../ERD.md#rooms), [GAMES](../ERD.md#games) |
| 필수 ADR | [ADR-0009 UTC 저장과 서비스 시간대 변환](../adr/platform/0009-utc-time-standard.md) |

### 기능 규칙

- 로그인 사용자는 게임 중심 또는 사람 중심 방을 생성할 수 있다.
- `GAME_FOCUSED`는 게임 선택이 필수이고, `PERSON_FOCUSED`는 게임을 선택하지 않을 수 있다.
- P0 지역은 홍대로 고정하며 생성 요청에서 지역을 받지 않는다.
- 권장 경험 수준은 참가 제한이 아니며, 룰마스터 여부는 주최자의 자기 선언이다.
- 입력 필드와 검증 규칙은 API 계약을 따른다.

### 완료 기준

- `AC1` 유효한 요청으로 생성한 방이 공통 정원·최초 상태·시간 규칙을 만족한다.
- `AC2` 방 유형별 게임 선택 규칙을 위반한 요청은 API 계약의 오류로 거절한다.
- `AC3` 생성자는 주최자로 기록되고 방 관계자 범위의 생성 결과를 받는다.
- `AC4` 생성된 방의 지역은 홍대로 저장되며 내 모임의 개설 목록에서 확인할 수 있다.

### 제외 범위

- 홍대 외 지역 선택
- 반복 모임 생성
- 사용자 입력 게임 생성
- 룰마스터 숙련도와 자격 검증

## ROOM-04 방 수정

### 구현 컨텍스트

| 데이터 모델 | [ROOMS](../ERD.md#rooms), [GAMES](../ERD.md#games) |
| 필수 ADR | [ADR-0012 요청 경계 방 상태 정합화](../adr/room/0012-room-request-boundary-state-reconciliation.md), [ADR-0005 방 참가 동시성 제어](../adr/participation/0005-room-participation-optimistic-locking.md), [ADR-0009 UTC 저장과 서비스 시간대 변환](../adr/platform/0009-utc-time-standard.md), [ADR-0016 수정 API HTTP 메서드](../adr/platform/0016-p0-update-api-http-method.md) |

### 기능 규칙

- 주최자만 저장된 시작 시각 전의 모집 중인 방을 수정할 수 있다.
- 주최자 외 현재 `ACTIVE` 참가자가 있으면 수정할 수 없다.
- 방 수정은 부분 수정이며, 생략과 `null`의 의미는 API 계약을 따른다.
- 방 유형, 지역과 상태는 수정 입력으로 변경할 수 없다.
- 정원 변경은 공통 정원 규칙과 동시성 ADR을 따른다.

### 완료 기준

- `AC1` 수정 가능한 방의 허용 필드만 변경되고 나머지 값은 유지된다.
- `AC2` 주최자가 아니거나 수정 가능 상태·시간·참가자 조건을 충족하지 않으면 계약된 오류를 반환한다.
- `AC3` 방 유형, 지역 또는 상태를 포함한 요청은 API 계약에 따라 거절한다.
- `AC4` 정원 변경과 참가 요청이 겹쳐도 저장 불변식이 유지된다.

### 제외 범위

- 주최자 이전
- 방 유형과 지역 변경
- 수정 API를 통한 상태 변경
- 현재 `ACTIVE` 참가자가 있는 방의 내용 변경 협의 기능

## ROOM-05 방 취소·종료

### 구현 컨텍스트

| API 계약 | [방 취소](../API.md#room-05-방-취소), [방 종료](../API.md#room-05-방-종료) |
| 공통 규칙 | [방 상태](../P0-spec.md#방-상태roomstatus), [권한과 공개 범위](../P0-spec.md#권한과-공개-범위), [시간 경계](../P0-spec.md#시간-경계), [상태 정합성과 동시 변경](../P0-spec.md#상태-정합성과-동시-변경) |
| 데이터 모델 | [ROOMS](../ERD.md#rooms) |
| 필수 ADR | [ADR-0012 요청 경계 방 상태 정합화](../adr/room/0012-room-request-boundary-state-reconciliation.md), [ADR-0009 UTC 저장과 서비스 시간대 변환](../adr/platform/0009-utc-time-standard.md), [ADR-0016 수정 API HTTP 메서드](../adr/platform/0016-p0-update-api-http-method.md) |

### 기능 규칙

- 주최자만 공통 상태 규칙이 허용하는 방을 취소하거나 종료할 수 있다.
- 취소는 방 행을 삭제하지 않고 최종 상태로 변경한다.
- 종료 요청은 API 계약이 허용하는 상태 값만 받으며 시간 경계 판정은 공통 규칙을 따른다.
- 자동 종료는 `ROOM-06 방 상태 정합화`에서 검증한다.

### 완료 기준

- `AC1` 허용된 취소 요청은 방을 취소 상태로 변경하고 API 계약의 결과를 반환한다.
- `AC2` 허용된 수동 종료 요청은 방을 종료 상태로 변경하고 API 계약의 결과를 반환한다.
- `AC3` 권한·상태·시간 조건을 충족하지 않는 요청은 계약된 오류를 반환한다.
- `AC4` 최종 상태로 변경된 방은 공통 상태·공개 범위 규칙을 일관되게 따른다.

### 제외 범위

- 방의 물리 삭제
- 취소·종료 철회와 재개방
- 방 변경·취소·종료 알림
- 시작 전 수동 종료

## ROOM-06 방 상태 정합화

### 구현 컨텍스트

| 구분 | 정본 |
| --- | --- |
| API 계약 | [방 상태 계약](../API.md#roomstatus) |
| 공통 규칙 | [방 상태](../P0-spec.md#방-상태roomstatus), [시간 경계](../P0-spec.md#시간-경계), [상태 정합성과 동시 변경](../P0-spec.md#상태-정합성과-동시-변경) |
| 데이터 모델 | [ROOMS](../ERD.md#rooms) |
| 필수 ADR | [ADR-0012 요청 경계 방 상태 정합화](../adr/room/0012-room-request-boundary-state-reconciliation.md), [ADR-0005 방 참가 동시성 제어](../adr/participation/0005-room-participation-optimistic-locking.md), [ADR-0009 UTC 저장과 서비스 시간대 변환](../adr/platform/0009-utc-time-standard.md) |
| 검증 환경 | [ADR-0010 H2와 PostgreSQL 테스트 경계](../adr/platform/0010-h2-postgresql-test-boundary.md) |

### 기능 규칙

- 방 목록·상세·내 모임 조회와 상태에 의존하는 명령은 원래 동작 전에 현재 방 상태를 정합화한다.
- 상태 전이 조건은 P0 공통 상태 규칙, 시간 비교는 공통 시간 경계와 시간 ADR을 따른다.
- 상태 보정의 트랜잭션·재시도·충돌 처리는 ADR-0012와 ADR-0005를 따른다.
- 요청이 없는 방을 정리하는 작업도 별도 전이 규칙을 만들지 않는다.

### 완료 기준

- `AC1` 시작 경계를 지난 방은 상태에 의존하는 조회와 명령에서 현재 상태로 판정된다.
- `AC2` 자동 종료 경계를 지난 방은 상태 정합화 후 종료 상태로 판정된다.
- `AC3` 목록과 내 모임은 상태 보정이 반영된 뒤 필터와 페이지를 계산한다.
- `AC4` 동시 보정이 다른 최종 상태를 덮어쓰지 않으며, 재시도 실패는 API 계약의 오류로 귀결된다.
- `AC5` 경계 시각과 동시 요청 검증은 PostgreSQL 기반 통합 테스트로 통과한다.

### 제외 범위

- 정확한 시각 실행을 위한 외부 스케줄링 시스템
- 다중 인스턴스 스케줄러 조정
- 요청이 없는 방의 상태 전환 시각 SLA
- 상태별 별도 전이 구현
