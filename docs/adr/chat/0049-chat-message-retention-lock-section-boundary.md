# ADR-0049: 최종 상태 채팅 메시지 보관·삭제와 잠금 구간 실행 경계

## 맥락

[ADR-0034](0034-chat-message-retention-and-deletion.md)는 최종 상태 방의 메시지를 30일 보관한 뒤 일일 스케줄에서 소량 묶음으로 삭제하고, ShedLock을 얻은 한 실행만 작업을 소유하도록 정했다. 그 결정은 공통 스케줄 잠금이 전체 배치 조정 구간을 감싸고 삭제 지연을 만료 뒤 24시간으로 제한하는 것을 전제로 했다.

#289 구현에서 대표 batch(방 50개·메시지 5,000개·방별 100개 chunk)의 처리 시간이 실행 환경에 따라 95ms에서 3.2초까지 측정됐다. 적체가 커지면 잠금 임대가 먼저 만료되어 다른 인스턴스가 같은 주기의 삭제를 시작할 수 있다. 반대로 작업량을 제한하면 정상 만료 방이 다음 일일 실행으로 이월되어 24시간 상한이 깨질 수 있다.

따라서 보관 기간과 접근 차단 시점은 유지하고, 잠금 구간과 실행 상한의 관계만 다시 정한다. ADR-0034의 결정 본문은 수정하지 않고 이 ADR로 대체한다.

## 검토한 대안

| 대안 | 장점 | 비용·위험 | 판단 |
| --- | --- | --- | --- |
| 한 잠금 구간의 작업량만 제한하고 남은 방은 다음 일일 실행으로 이월 | 구현이 단순하고 임대를 지킨다. | 삭제가 48시간 이상 늦어질 수 있다. | 제외 |
| 잠금 임대를 적체 처리에 필요한 만큼 길게 두고 한 구간에서 완주 | 구간 재획득이 필요 없다. | 처리 시간이 환경에 따라 크게 달라 임대 상한을 안전하게 정하기 어렵다. | 제외 |
| 임대보다 짧은 실행 상한으로 중단하고 같은 cron 실행에서 잠금을 다시 얻어 이어 처리 | 임대 경계와 24시간 상한을 함께 지킨다. | cron 실행의 구간 수 상한과 적체 관측이 필요하다. | 선택 |
| 스케줄 주기를 짧게 변경 | 적체를 여러 실행으로 분산한다. | 일일 스케줄 계약과 보관 결정을 함께 바꿔야 한다. | 제외 |

## 결정

1. ADR-0034의 30일 보관·최종 상태 접근 차단·묶음 단위 독립 트랜잭션·멱등 삭제 결정을 승계한다.
2. 만료 삭제에는 [ADR-0038](../platform/0038-multi-instance-session-and-scheduler-coordination.md)의 PostgreSQL ShedLock 계약을 사용한다. `V16__create_p1_chat_retention_schema.sql`은 `SHEDLOCK` 테이블만 생성하며, 채팅방 스키마와 기존 ROOM 초기화는 [ADR-0045](0045-chat-room-schema-and-backfill-boundary.md)가 소유한다.
3. 한 잠금 구간은 잠금 임대보다 짧은 실행 상한 안에서만 작업한다. 상한에 도달하면 완료를 기록하지 않고 중단한다.
4. 실행 상한과 질의 시간 상한의 합은 `lockAtMostFor`보다 짧아야 하며, 조건을 만족하지 않으면 애플리케이션 기동을 실패시킨다.
5. 상한에 걸린 적체는 다음 일일 스케줄로 미루지 않는다. 같은 cron 실행에서 잠금을 다시 얻어 정해진 구간 수 상한까지 이어 처리한다. 잠금을 얻지 못하면 대기하지 않고 해당 실행을 끝낸다.
6. 구간 수 상한을 모두 소진하고도 적체가 남으면 삭제가 만료 뒤 24시간을 초과할 수 있다. 경고 로그와 전용 metric으로 알리고 실행 상한·구간 수·주기를 조정한다.
7. 성공·삭제 건수·삭제 지연·실패·구간 중단을 메트릭과 로그에 남긴다. 메시지 본문, 세션 식별자와 내부 사용자 식별자는 기록하지 않는다.
8. 잠금 이름, `lockAtMostFor`, 실행 상한, 질의 시간 상한, 구간 수 상한과 경고 기준의 구체적인 값은 `CHAT-04` 구현 이슈가 측정 근거와 함께 확정한다.

완전 삭제는 운영 live DB의 `CHAT_MESSAGES` 행 삭제를 뜻한다. RDS 자동 백업의 개별 행은 선택 삭제하지 않으며 백업은 ADR-0021의 보존주기가 끝나면 만료된다.

## 결과

- 한 잠금 구간이 임대를 넘기지 않아 임대 만료에 따른 중복 실행을 줄인다.
- 실행 상한에 걸린 적체가 같은 cron 실행에서 이어 처리되므로 24시간 상한을 유지할 수 있다.
- 구간 수 상한을 초과하는 적체는 metric으로 드러나 운영 조정 대상이 된다.

## 보류 및 재검토

- 지금 하지 않는 것: 일일 스케줄 주기 변경, 잠금 임대 갱신, 채팅 전용 스케줄러 서비스, 신고 메시지 예외 보관
- 다시 검토할 조건: 구간 수 상한 초과가 반복되거나 신고·법적 보존 요구가 생길 때
