# ADR-0049: 최종 상태 채팅 메시지 보관·삭제와 잠금 구간 실행 경계

- 결정일: 2026-08-04

## 맥락

[ADR-0034](0034-chat-message-retention-and-deletion.md)는 최종 상태 방의 메시지를 30일 보관한 뒤 일일 스케줄에서 소량 묶음으로 삭제하고, ShedLock을 얻은 한 실행만 작업을 소유하도록 정했다. 그 결정은 "공통 스케줄 잠금은 전체 배치 조정 구간을 감싼다"를 전제하고, 삭제 지연 상한을 만료 뒤 24시간으로 정했다.

#289 구현에서 대표 batch(방 50개·메시지 5,000개·방별 100개 chunk)의 처리 시간이 실행 환경에 따라 95ms에서 3.2초까지 측정됐다. 한 잠금 구간이 전체 적체를 감싸야 한다는 전제와, 그 구간이 항상 잠금 임대 안에서 끝나야 한다는 요구를 동시에 만족할 수 없다. 적체가 커지면 임대가 먼저 만료돼 다른 인스턴스가 같은 주기의 잠금을 얻고 중복 스캔·삭제를 시작한다. 반대로 한 구간의 작업량을 제한하면 임대는 지키지만 상한에 걸린 정상 만료 방이 다음 일일 실행으로 이월돼 첫 실행 대기와 이월 대기가 합쳐지고 24시간 상한이 깨진다.

따라서 보관 기간과 접근 차단 시점은 그대로 두고, 잠금 구간과 실행 상한의 관계만 다시 정한다. ADR-0034의 결정 본문은 사후에 수정하지 않고 이 ADR로 대체한다.

이번 결정의 판단 기준은 다음과 같다.

- 한 잠금 구간의 작업이 항상 그 구간의 임대 안에서 끝날 것
- 만료된 방의 삭제가 만료 뒤 24시간 안에 완료될 것
- 두 조건을 함께 만족할 수 없는 상황을 값 조정 대상으로 관측할 수 있을 것
- 30일 보관 기간, 최종 상태 접근 차단과 묶음 단위 독립 트랜잭션은 ADR-0034 결정을 유지할 것

## 검토한 대안

| 대안 | 장점 | 비용·위험 | 판단 |
| --- | --- | --- | --- |
| 한 잠금 구간의 작업량만 제한하고 남은 방은 다음 일일 실행으로 이월 | 구현이 가장 단순하고 임대를 항상 지킨다. | 상한에 걸린 정상 만료 방의 삭제가 48시간 이상 늦고, 지속 적체에서는 지연 상한이 사라진다. | 제외 |
| 잠금 임대를 적체 처리에 필요한 만큼 길게 두고 한 구간에서 완주 | 구간 재획득이 필요 없다. | 임대 보유 인스턴스가 죽으면 그 임대만큼 다음 실행이 막히고, 처리 시간이 환경에 따라 30배 이상 벌어져 임대 상한을 미리 정할 수 없다. | 제외 |

| 스케줄 주기를 짧게 바꿔 적체를 여러 cron 실행으로 분산 | 구간 재획득 없이 지연을 줄인다. | `CHAT-04-AC4`의 일일 스케줄 계약과 ADR-0034의 주기 결정을 함께 바꿔야 하고, 적체가 없을 때도 주기마다 조회가 발생한다. | 제외 |

## 결정

1. ADR-0034의 보관·삭제 결정을 그대로 승계한다. `RECRUITING`·`CLOSED` 방의 메시지는 삭제하지 않는다. 방이 `CANCELED` 또는 `FINISHED`로 전환되면 일반 사용자 접근을 즉시 차단하고, `room.contract.RoomTerminalStateReached`를 받은 `chat`의 동기 listener가 같은 트랜잭션에서 `CHAT_ROOMS.purge_after`를 전환 시각에서 30일 뒤로 설정한다. 하루 한 번 Spring Scheduler가 `purge_after`가 지난 채팅방을 조회하고, 만료된 `CHAT_MESSAGES`를 설정 가능한 소량 묶음으로 물리 삭제한다. 각 묶음은 독립 트랜잭션이며 성공한 묶음은 실패한 묶음 때문에 롤백되지 않는다. 삭제를 마친 채팅방은 `messages_purged_at`을 기록하고, 작업은 `purge_after <= now`이면서 `messages_purged_at IS NULL`인 대상만 처리해 겹쳐 실행되더라도 같은 최종 결과로 수렴한다. 실패한 묶음은 무한 즉시 재시도하지 않는다.
2. 만료 삭제 스케줄에는 [ADR-0038](../platform/0038-multi-instance-session-and-scheduler-coordination.md)의 PostgreSQL ShedLock 계약을 사용하고, 잠금을 얻은 실행만 삭제 작업을 소유한다. `V16__create_p1_chat_retention_schema.sql`은 `SHEDLOCK` 테이블만 생성하며 기존 `ROOMS`를 조회하거나 `CHAT_ROOMS` 행을 삽입·갱신하지 않는다. 채팅방 스키마와 기존 ROOM 초기화 경계는 [ADR-0045](0045-chat-room-schema-and-backfill-boundary.md)가 소유한다.
3. 한 잠금 구간은 잠금 임대보다 짧은 실행 상한 안에서만 작업한다. 만료 방 batch를 조회하기 전과 각 방의 메시지 chunk를 처리하기 전에 상한 도달을 확인하고, 도달하면 완료를 기록하지 않고 중단한다.
4. 만료 방 조회, 메시지 chunk 조회·삭제와 완료 기록 질의에 질의 시간 상한을 둔다. 마지막 상한 확인 뒤에도 진행 중인 chunk의 질의가 남으므로, `실행 상한 + 3 × 질의 상한 < lockAtMostFor`를 애플리케이션 기동 시점에 검증하고 만족하지 않으면 기동을 실패시킨다.
5. 실행 상한에서 중단된 적체는 다음 일일 스케줄로 미루지 않는다. 같은 cron 실행에서 잠금을 다시 얻어 정해진 구간 수 상한까지 이어 처리한다. 각 구간은 자신의 임대 안에서만 작업하므로 한 시점에 한 실행만 작업을 소유하는 계약은 유지된다. 잠금을 얻지 못하면 대기하지 않고 그 cron 실행을 끝낸다.
6. 구간 수 상한을 모두 소진하고도 적체가 남으면 삭제가 만료 뒤 24시간을 초과할 수 있다. 이 경우를 정상 경로로 두지 않고 경고 로그와 전용 metric으로 알린 뒤 실행 상한·구간 수·주기를 조정한다.
7. 성공·삭제 건수·삭제 지연·실패·구간 중단을 메트릭과 로그에 남기고 스케줄 실패 알림을 발생시킨다. 메시지 본문, 세션 식별자와 내부 사용자 식별자는 기록하지 않는다.
8. 잠금 이름, `lockAtMostFor`, 실행 상한, 질의 시간 상한, 구간 수 상한과 실행시간 경고 기준의 구체적인 값은 이 ADR이 고정하지 않는다. `CHAT-04` 구현 이슈가 측정 근거와 함께 확정하고 `CHAT-04` 정본에 적는다. 위 결정 3·4·5·6의 구조는 값 선택과 무관하게 유지한다.

완전 삭제는 운영 live DB의 `CHAT_MESSAGES` 행 삭제를 뜻한다. 이미 생성된 RDS 자동 백업에서는 개별 행을 선택 삭제하지 않으며, 해당 백업은 ADR-0021의 7일 보존주기가 끝나면 만료된다.

## 결과

- 얻는 것:
    - 한 잠금 구간이 임대를 넘기지 않으므로 임대 만료로 두 인스턴스가 같은 주기의 삭제를 겹쳐 실행하지 않는다.
    - 구간 수 상한 내에서 해소되는 적체는 같은 cron 실행에서 이어 처리되므로 24시간 삭제 상한을 유지한다.
    - 처리 시간이 환경에 따라 크게 달라져도 구간 수로 흡수하고, 흡수하지 못하는 적체는 metric으로 드러난다.
- 감수할 비용·위험:
    - 한 cron 실행이 여러 잠금 구간을 사용하므로 구간 사이에 다른 인스턴스가 잠금을 얻을 수 있다. 삭제가 멱등이라 최종 결과는 같지만 소유 인스턴스가 구간마다 달라질 수 있다.
    - 구간 수 상한은 유한하므로 그보다 큰 적체가 지속되면 24시간 상한을 지킬 수 없고 값 조정이 필요하다.
    - 질의 시간 상한 때문에 느린 질의가 실패로 관측될 수 있고, 해당 묶음은 다음 실행에서 다시 처리된다.
- 후속 작업:
    - `CHAT-04` 구현 이슈에서 결정 8의 값을 측정 근거와 함께 확정하고 `CHAT-04` 정본에 반영한다.
    - 운영 적체와 구간 중단 metric을 관측한 뒤 실행 상한·구간 수를 재조정한다.

## 보류 및 재검토

- 지금 하지 않는 것: 일일 스케줄 주기 변경, 잠금 임대 갱신(lock extension), 채팅 전용 스케줄러 서비스나 Quartz 클러스터 도입, 신고 메시지 예외 보관
- 보류 이유: 구간 재획득으로 임대 경계와 24시간 상한을 함께 지킬 수 있어 주기·인프라를 바꿀 필요가 없다. P1에 신고·분쟁 처리 기능이 없어 예외 보관 대상도 없다.
- 다시 검토할 조건: 구간 수 상한 초과가 운영에서 반복 관측될 때, 또는 신고·법적 보존 요구가 생겨 보관 기간에 예외가 필요할 때
