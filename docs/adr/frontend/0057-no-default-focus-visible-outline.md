# ADR-0057: 기본 `:focus-visible` 아웃라인을 전역에서 제거

- 상태: 승인됨
- 작성일: 2026-08-12
- 결정일: 2026-08-09
- 관련: `frontend/src/styles.css`의 전역 `a:focus-visible, button:focus-visible, input:focus-visible, select:focus-visible, textarea:focus-visible { outline: none; }` 규칙, [PR #635](https://github.com/bamsongi-club/albam-mate/pull/635) 리뷰 스레드
- 대체 대상: 없음
- 후속 ADR: 없음

## 맥락

기본 브라우저 `:focus-visible` 아웃라인(주황 3px 링)이 알밤메이트의 시각 톤과 맞지 않는다는 지적이 반복됐다. WCAG 2.4.7(포커스 보임)은 키보드 사용자가 현재 포커스 위치를 시각적으로 식별할 수 있어야 한다고 요구하므로, 완전 제거는 접근성 원칙과 충돌한다. 이 절충을 팀이 한 번 논의하고 결정했다는 사실이 코드에만 남아 있어, PR 리뷰마다 같은 지적("포커스 표시가 없다")이 근거 없는 결함으로 반복 제기됐다(PR #635 기준 이번이 처음이 아님).

판단 기준은 두 가지였다.

- 접근성: 키보드 사용자가 포커스 위치를 잃지 않아야 한다.
- 시각 톤: 서비스 전반의 색감·질감과 어긋나는 표시를 넣지 않는다.

## 검토한 대안

| 대안 | 장점 | 비용·위험 | 판단 |
| --- | --- | --- | --- |
| 입력창만 포커스 링 유지, 나머지 제거 | 폼 접근성은 지키면서 링크·버튼의 시각 노이즈를 줄인다. | 링크·버튼 키보드 탐색 시 위치를 알 방법이 hover 스타일뿐이라 여전히 부족하다. | 제외 |
| 전체에 은은한 포커스 표시(낮은 대비 `box-shadow` 등) 적용 | WCAG 2.4.7을 만족하면서 기존 주황 아웃라인보다 튀지 않는다. | 별도 디자인 확정이 필요하고, 이번 결정 시점에는 준비되지 않았다. | 제외 |
| 전역 `:focus-visible` 아웃라인을 완전히 제거 | 시각적으로 가장 깔끔하고 즉시 적용 가능하다. | 키보드 전용 사용자가 링크·버튼·폼 컨트롤의 현재 포커스 위치를 시각적으로 확인할 수 없다. 입력창은 깜빡이는 캐럿으로만 위치가 드러난다. | 선택 |

## 결정

`frontend/src/styles.css`에서 `a`, `button`, `input`, `select`, `textarea`의 `:focus-visible` 아웃라인을 전역으로 `outline: none`으로 제거한다. 입력 요소는 깜빡이는 캐럿이 포커스 위치를 대신 드러낸다고 보고, 그 외 인터랙티브 요소(링크·버튼)는 별도 포커스 표시를 두지 않는다.

이 결정은 WCAG 2.4.7과의 트레이드오프를 인지한 채로 내려졌다. 시각 톤을 접근성 대체 표시보다 우선했으며, 되돌리려면 이 ADR을 대체하는 새 ADR과 함께 승인이 필요하다.

## 결과

- 얻는 것:
    - 링크·버튼·폼 컨트롤에 브라우저 기본 주황 포커스 링이 노출되지 않아 서비스 전반의 시각 톤이 일관된다.
    - 컴포넌트마다 포커스 스타일을 개별 결정할 필요 없이 전역 규칙 하나로 통일된다.
- 감수할 비용·위험:
    - 키보드 전용 사용자가 링크·버튼을 탭으로 순회할 때 현재 포커스 위치를 시각적으로 확인할 수 없다(WCAG 2.4.7 미충족).
    - `.filter-match-switch:focus-visible`(`frontend/src/styles.css`)은 토글 스위치의 상태 변화가 hover만으로 드러나지 않는다는 이유로 이 결정 이후에도 `outline: 2px solid var(--accent)`를 개별로 유지하고 있다. 전역 규칙과 어긋나는 예외이며, 이 ADR은 그 예외를 사후 승인하지 않는다. 접근성 예외가 필요한 컴포넌트가 더 있다면 별도로 검토해 이 ADR을 갱신하거나 대체해야 한다.
- 후속 작업:
    - 리뷰에서 이 지적이 다시 나오면 이 ADR을 근거로 반박하고, 새로운 사실관계 없이 결정을 재논의하지 않는다.
    - `.filter-match-switch`처럼 전역 규칙과 다른 예외가 이미 있는지, 앞으로 필요한지 별도 이슈로 정리한다.

## 보류 및 재검토

- 지금 하지 않는 것: 은은한 대체 포커스 표시(낮은 대비 `box-shadow` 등) 도입, 컴포넌트별 예외 정책 수립
- 보류 이유: 이번 결정 시점에는 시각 톤을 우선했고, 대체 표시안이 준비되지 않았다.
- 다시 검토할 조건: 접근성 감사·실사용자 피드백으로 키보드 탐색 불가가 실제 문제로 확인되거나, 시각 톤을 해치지 않는 대체 포커스 표시안이 마련될 때
