# ADR-0037: ROOM 대기열을 단일 최신 상태로 저장하고 자동 승격을 원자적으로 처리

- 상태: 대체됨
- 작성일: 2026-07-31
- 결정일: 2026-08-01
- 관련: [P1 PART-04](../../p1/room.md#part-04-선착순-대기열과-자동-승격), [P1 대기 API 계약](../../API.md#part-04-대기-등록재신청), [ERD](../../ERD.md), [ADR-0005](0005-room-participation-optimistic-locking.md), [ADR-0035](../room/0035-room-status-action-eligibility-separation.md), [ADR-0036](../room/0036-bounded-room-state-transition-processing.md)
- 대체 대상: 없음
- 후속 ADR: [ADR-0043](0043-room-waitlist-persistence-conditional-transition-retry.md)

## 맥락

P1은 시작 전 정원이 찬 ROOM에 별도로 대기를 신청하고, 현재 대기 상태와 본인 순번을 조회하며, 참가 취소로 생긴 빈자리에 첫 대기자를 자동 승격하는 기능을 추가한다. 동일 사용자의 중복 신청은 기존 순서를 유지하고, 취소 뒤 재신청은 대기열 맨 뒤로 이동해야 한다. 시작 시각 도달과 ROOM 취소 뒤에는 남은 대기도 종료 상태로 조회할 수 있어야 한다.

이 계약을 저장하는 방식으로 신청·취소마다 이력을 추가하는 모델과 ROOM·사용자별 최신 상태 하나를 유지하는 모델을 선택해야 한다. 또한 자동 승격은 ROOM의 참가 인원과 상태, 기존 참가 관계, 첫 `WAITING` 대기 관계를 함께 바꾸므로, 참가 취소만 반영되거나 같은 빈자리에 둘 이상이 승격되는 부분 성공을 막을 일관성 경계가 필요하다.

이 결정은 다음 기준을 우선한다.

- 같은 ROOM과 사용자의 현재 대기 결과를 하나의 정본에서 조회한다.
- 중복 신청은 순서를 바꾸지 않고, 취소 뒤 재신청은 새로운 신청 순서를 받는다.
- 참가 취소와 첫 대기자 승격 사이에 부분 성공 상태를 남기지 않는다.
- 현재 ROOM 낙관적 락 기준선을 측정하기 전에 임의로 더 강한 잠금 전략을 채택하지 않는다.
- 신규 대기와 재신청처럼 `WAITING`을 활성화하는 요청만 ROOM의 빈자리 배정 판단과 충돌시키고, 중복 신청과 대기 취소까지 ROOM 버전을 강제로 증가시키지 않는다.
- 동시 대기 취소와 자동 승격 중 하나만 현재 `WAITING` 상태를 변경하게 한다.
- 전체 대기 이력 조회와 운영 감사 기능은 현재 범위에 추가하지 않는다.

## 결정

같은 ROOM과 사용자의 대기 관계는 하나의 레코드로 저장하고 데이터베이스 제약으로 중복 레코드를 허용하지 않는다. `WAITING`, `PROMOTED`, `CANCELED`, `EXPIRED`, `ROOM_CANCELED`는 이 레코드의 최신 결과를 나타낸다. 현재 범위에서는 신청과 취소가 반복될 때마다 별도 이력 레코드를 추가하지 않는다.

대기 순서는 서버가 대기 신청을 성공으로 확정한 순서를 기준으로 한다. 이미 `WAITING`인 사용자의 중복 신청은 상태와 순서 기준을 변경하지 않는다. 취소 뒤 재신청은 같은 레코드를 `WAITING`으로 바꾸고 순서 기준을 새로 기록해 대기열 맨 뒤에 배치한다. 구체적인 열과 동률 해소 키, 인덱스는 ERD와 구현 이슈에서 확정하되 이 FIFO 의미를 바꾸지 않는다.

시작 전 참가 취소로 빈자리가 생기면 참가 취소, FIFO상 첫 `WAITING` 대기자의 `PROMOTED` 전이, 참가 관계의 `ACTIVE` 전이 또는 생성, ROOM 참가 인원과 상태 변경을 같은 ROOM 처리 트랜잭션에서 수행한다. 승격 시점에 기존 참가 자격, ROOM 정원·시작 경계와 대기 상태를 최신 값으로 다시 검사하고, 확정된 변경 중 하나라도 실패하면 전부 롤백한다. 시작 시각 도달과 ROOM 취소로 남은 대기를 종료하는 처리도 해당 ROOM 상태 판정과 같은 일관성 경계에서 수행한다.

정원·ROOM 상태 변경은 ADR-0005의 `Room.@Version`, 독립 트랜잭션과 제한 재시도를 유지한다. 대기 신청·재신청·취소·승격·만료·ROOM 취소는 해당 레코드의 현재 상태가 허용된 출발 상태일 때만 바뀌는 조건부 갱신으로 처리하고, 대기 레코드에는 별도 낙관적 락 버전을 두지 않는다.

신규 대기와 `CANCELED` 등 종료 상태에서의 재신청처럼 대기 관계를 `WAITING`으로 활성화하는 요청은 대기 관계 변경과 같은 트랜잭션에서 ROOM 버전을 증가시킨다. 버전 충돌이 발생하면 대기 관계 변경을 포함한 전체 요청을 롤백하고 ADR-0005의 제한 안에서 최신 ROOM 상태·정원·시작 경계와 사용자 자격부터 다시 판단한다. 재시도 시 ROOM이 더 이상 대기 가능하지 않으면 `WAITING`을 남기지 않고 최신 업무 결과를 반환한다. 이미 `WAITING`인 중복 신청과 `WAITING → CANCELED` 대기 취소는 ROOM의 빈자리 배정 결정을 새로 만들지 않으므로 ROOM 버전을 강제로 증가시키지 않는다.

이 경계에서 대기 활성화가 먼저 커밋되면 동시 참가 취소가 ROOM 버전 충돌 뒤 다시 읽은 첫 대기자를 승격한다. 참가 취소가 먼저 커밋되어 활성 대기자 없음과 빈자리를 확정하면 동시 대기 활성화가 버전 충돌 뒤 최신 `RECRUITING` 상태를 읽고 대기 관계를 만들지 않는다. 따라서 활성 대기가 있는 ROOM을 `RECRUITING`으로 확정하는 상태를 허용하지 않는다.

자동 승격은 FIFO 순서상 현재 첫 `WAITING` 레코드에 `WAITING → PROMOTED` 조건부 갱신을 시도한다. 동시 취소나 다른 처리로 그 레코드가 이미 바뀌어 갱신 결과가 0건이면, 먼저 확정된 최신 상태를 그대로 보존하고 다음 현재 `WAITING` 후보를 계속 검사한다. 이를 위해 `SKIPPED` 같은 별도 상태를 추가하지 않는다. 대기 취소는 `WAITING → CANCELED`, 시작 경계와 ROOM 취소는 남은 `WAITING`을 각각 `EXPIRED`, `ROOM_CANCELED`로 조건부 전이한다.

조건부 대기 전이와 참가·ROOM 변경은 같은 트랜잭션에서 커밋하거나 함께 롤백한다. 구현은 모든 관련 경로에서 일관된 데이터베이스 변경 순서를 사용하고, 조건부 갱신 결과가 0건일 때 최신 상태를 다시 읽어 중복 요청·업무 오류·다음 승격 후보를 구분한다. 정확한 열, 동률 해소 키, 인덱스와 Repository 쿼리는 ERD와 구현 이슈에서 확정하되 이 상태 전이와 FIFO 의미를 바꾸지 않는다.

비관적 락과 `SKIP LOCKED`, 모든 대기 변경의 ROOM 버전 강제 증가는 현재 선택하지 않는다. ROOM-10 측정에서 조건부 갱신 충돌·재조회 또는 ROOM 낙관적 락 재시도 비용이 실제 문제로 확인되고 사용자가 비교를 승인한 경우에만 후속 ADR로 잠금 전략 변경을 검토한다.

## 결과

- 얻는 것:
    - 현재 대기 상태와 중복 신청 여부를 ROOM·사용자별 하나의 레코드에서 일관되게 판단할 수 있다.
    - 참가 취소와 승격의 부분 성공을 막고 빈자리당 한 명만 승격하는 검증 경계를 명확히 할 수 있다.
    - 대기 취소와 자동 승격이 경합해도 먼저 확정된 상태를 덮어쓰지 않고 다음 현재 대기자를 승격할 수 있다.
    - 대기 활성화와 빈자리 복귀가 경합해도 ROOM 버전 충돌 뒤 최신 상태에서 다시 판단하므로 활성 대기가 있는 ROOM을 `RECRUITING`으로 확정하지 않는다.
    - 중복 신청과 대기 취소는 ROOM 버전을 증가시키지 않으면서 현재 ROOM 낙관적 락을 기준선으로 측정할 수 있다.
- 감수할 비용·위험:
    - 전체 대기 변경 이력을 보존하지 않으므로 향후 감사 기능이 필요하면 별도 이력 모델이 필요하다.
    - 상한 없는 대기열의 순번 조회와 첫 대기자 선택 성능은 실제 실행 계획과 인덱스로 검증해야 한다.
    - 조건부 갱신 결과가 0건인 경우마다 최신 상태 재조회와 결과 분기가 필요하다.
    - 전용 조건부 갱신과 일괄 종료 쿼리가 영속성 컨텍스트의 오래된 Entity 상태와 섞이지 않도록 구현 경계를 검증해야 한다.
    - 같은 ROOM의 신규 대기·재신청은 ROOM 버전에서 참가 변경이나 다른 대기 활성화와 충돌해 제한 재시도 비용을 부담한다.
- 후속 작업:
    - 별도 버전 열 없는 단일 최신 상태 레코드의 ERD·Flyway 제약과 FIFO 조회 인덱스를 확정한다.
    - 허용된 출발 상태를 검사하는 조건부 전이와 갱신 결과 분기, 일관된 데이터베이스 변경 순서를 구현한다.
    - PostgreSQL에서 신규 대기·재신청과 참가 취소의 두 커밋 순서, 동시 대기 취소·승격, 복수 참가 취소와 시작·ROOM 취소 경계의 불변식을 검증한다.

## 보류 및 재검토

- 지금 하지 않는 것: 전체 대기 이벤트 이력, 대기 레코드별 버전, 비관적 락·`SKIP LOCKED`, 모든 대기 변경의 ROOM 버전 강제 증가, 분산 락과 외부 작업 큐
- 보류 이유: 현재 API는 최신 상태와 본인 순번만 요구하며, 조건부 상태 전이와 기존 ROOM 낙관적 락으로 기준선을 구현·측정할 수 있다.
- 다시 검토할 조건: 운영 감사나 이력 복원이 필요해지거나, 재현 가능한 측정에서 대기 활성화의 ROOM 버전 충돌·재시도, 조건부 갱신 충돌·재조회 또는 FIFO 조회 비용이 실제 문제로 확인되어 사용자가 ROOM별 별도 대기열 조정 버전이나 다른 대안 비교를 승인할 때
