# ADR-0026: 게임 인원·시간 표시값과 검색 수치를 분리

- 상태: 승인됨
- 작성일: 2026-07-31
- 결정일: 2026-08-03
- 관련: [SEARCH-01 게임 조건 검색](../../p1/search.md#search-01-게임-조건-검색), [P1 게임 데이터 정규화](../../P1-spec.md#게임-데이터-정규화), [게임 목록·검색 API](../../API.md#game-01-게임-목록검색), [ERD GAMES](../../ERD.md#games), [ADR-0015](0015-bgg-baseline-team-collected-game-list.md), [ADR-0008](../platform/0008-flyway-database-migrations.md), [ADR-0023](../platform/0023-p0-flyway-baseline-reset-player-count-stages.md)
- 대체 대상: 없음
- 후속 ADR: 없음

**결정 요약:** 인원·시간 표시 문자열은 유지하고, 같은 적재 배치에서 검증한 최소·최대 수치를 검색에 사용한다.

## 맥락

현재 게임의 가능 인원과 예상 시간은 `supported_player_count`, `estimated_play_time` 표시 문자열로 저장한다. 확보한 약 2,000건에는 표현 방식이 다양해, 사용자가 고른 인원이 범위에 포함되는지와 플레이 시간 구간을 DB에서 바로 판정하기 어렵다.

요청마다 문자열을 해석하면 같은 규칙이 목록·전체 건수 조회에 반복되고 파싱 실패가 사용자 요청 중에 발생한다. 반대로 문자열을 숫자로 완전히 대체하면 `2~4명`, `30~45분`처럼 화면에 보여 줄 표현과 입력 추적 근거를 잃는다.

따라서 표시 책임과 검색 책임을 분리할 저장 방식을 결정해야 한다.

## 검토한 대안

| 대안 | 장점 | 비용·위험 | 판단 |
| --- | --- | --- | --- |
| 요청마다 표시 문자열을 해석 | 스키마 변경이 없다. | 파싱 규칙이 조회 경로마다 퍼지고 DB의 전체 건수·페이지 조회와 맞추기 어렵다. | 제외 |
| PostgreSQL 정규식으로 문자열을 직접 검색 | 애플리케이션 파서를 줄일 수 있다. | 표현이 늘수록 쿼리와 검증이 복잡해진다. | 제외 |
| 표시 문자열을 숫자로 대체 | 검색 데이터가 단순하다. | 기존 화면 표현과 입력 추적 근거를 잃는다. | 제외 |
| 표시 문자열과 검증된 검색 수치를 함께 저장 | 표시와 검색 책임을 분리할 수 있다. | 두 표현의 정합성을 적재 단계에서 보장해야 한다. | 선택 |

## 결정

기존 인원·시간 표시 문자열은 유지하고, 검색에는 별도의 최소·최대 수치를 사용한다.

- 인원과 시간의 최소·최대는 각각 둘 다 있거나 둘 다 없어야 한다.
- 값이 있으면 양수이고 최소값이 최대값보다 크지 않아야 한다.
- 명시적으로 정보가 없으면 최소·최대를 모두 `NULL`로 둔다.
- 비어 있지 않은 표시값을 해석할 수 없거나 불변식을 어기면 적재 산출물을 만들지 않는다.

표시 문자열 해석과 검증은 카탈로그 준비 모듈이 한 번 수행한다. 같은 배치가 표시값과 검색 수치를 함께 검증·반영하며, 게임 검색 모듈은 요청 중 표시 문자열을 해석하지 않는다.

정본의 책임은 다음처럼 나눈다.

- 실제 열 이름·타입·DB 제약: `ERD.md`
- 필터 구간·누락값의 검색 결과·요청 파라미터: [P1 검색 명세](../../p1/search.md)와 `API.md`
- 입력별 변환 규칙·체크섬·품질 보고: 카탈로그 manifest와 적재 가이드
- 이 ADR: 표시값과 검색 수치를 분리하고 적재 단계에서 정합성을 보장하는 이유

`complexity`는 이미 숫자로 저장되므로 이 ADR의 표시값 분리 대상이 아니다. `0.00`과 유효 범위의 처리 규칙은 P1 검색 명세와 ERD에서 관리한다.

스키마는 ADR-0008에 따른 전진 Flyway 마이그레이션으로 변경하고, 카탈로그 값은 ADR-0015의 검수된 배치 절차로 반영한다. 이 ADR은 시간 구간, `10명 이상`의 검색 의미, 요청 파라미터와 물리 인덱스를 결정하지 않는다.

## 결과

- 얻는 것: 검색 모듈은 파싱 규칙을 알 필요 없이 DB 수치 조건으로 필터와 전체 건수를 계산하고, 기존 화면 표현도 유지한다.
- 감수할 비용·위험: 표시값과 검색 수치가 어긋나지 않도록 모든 적재 경로가 같은 변환·검증 절차를 거쳐야 한다.
- 후속 작업: 승인 후 ERD, 전진 마이그레이션과 카탈로그 변환·PostgreSQL 제약 테스트에 반영한다.

## 보류 및 재검토

- 지금 하지 않는 것: 표시 문자열 삭제, 요청 중 파싱, 전체 카탈로그 백필, 검색 인덱스 확정
- 보류 이유: P1은 현재 약 2,000건의 검증된 인원·시간 검색 수치만 준비한다.
- 다시 검토할 조건: 새로운 입력 표현이 현재 변환 계약으로 처리되지 않을 때, 전체 카탈로그를 검색 대상으로 확장할 때
