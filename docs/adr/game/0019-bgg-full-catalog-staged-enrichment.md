# ADR-0019: 전체 보드게임 카탈로그는 BASIC으로 확장하고 상세 정보는 단계적으로 보강

- 상태: 제안됨
- 작성일: 2026-07-28
- 결정일: 미정
- 관련: [제품 후속 기능 후보](../../PRD.md#후속-기능-후보-도입-차수-미정), [ERD GAMES](../../ERD.md#games), [게임 목록·검색 API](../../API.md#game-01-게임-목록검색), [ADR-0015](0015-bgg-baseline-team-collected-game-list.md), [ADR-0018](0018-expansion-type-and-relations.md)
- 대체 대상: 없음
- 후속 ADR: 없음

> 이 문서는 팀 논의를 위한 제안이다. 승인 전에는 구현 정본으로 사용하지 않는다.

## 맥락

P0에는 현재 2,000건의 게임 자료가 있다. 이 범위를 먼저 상세 데이터로 제공하고, 이후 전체 유효 보드게임과 확장을 식별 가능한 `BASIC` 목록으로 넓히고자 한다. 상세 정보는 실제 수요에 따라 단계적으로 보강한다.

확정 수량은 현재 2,000건뿐이다. BGG 스냅샷의 전체 행 수는 입력 후보의 측정값이지 제품 계약이 아니다. 다음 배치 규모는 품질·시간·비용을 측정한 뒤 정한다.

현재 자료는 BGG 데이터를 가공해 만들었으므로 JSON으로 재가공했다는 이유만으로 팀의 독립 데이터가 되지 않는다. 필드별 출처와 이용 근거를 다시 확인해야 한다.

BGG 승인 메일은 비상업적 XML API 사용과 공개 앱의 `Powered by BGG` 표시를 명시한다. 반면 번역·요약·AI/LLM 입력, 투표 재가공·결합, 이미지 재호스팅과 상업적 운영은 별도로 허용하지 않는다. 수익 모델을 도입하거나 이용 범위를 넓힐 때는 다시 확인해야 한다.

따라서 이 ADR은 다음 네 가지를 함께 결정한다.

1. 카탈로그의 확장 범위와 상세 상태
2. 출처별 이용 경계와 provenance
3. 의미가 다른 필드의 분리 원칙
4. 배치 검증·공개·적재 게이트

## 한눈에 보는 범위

~~~text
현재 2,000건 ── 출처 재확인 ── 첫 상세 제공
승인된 전체 후보 ── BASIC 등록 ── 우선순위별 상세 보강
                         │
                         ▼
              이용 범위·품질 게이트
                         │
                         ▼
                 Albam Mate DB·API
~~~

## 검토한 대안

| 대안 | 장점 | 비용·위험 | 판단 |
| --- | --- | --- | --- |
| 현재 2,000건만 운영 | 현재 범위와 품질을 유지하기 쉽다. | 목록 밖 게임을 찾거나 요청할 수 없다. | 제외 |
| 전체 후보를 한 번에 상세 보강 | 모든 게임에 같은 수준의 정보를 제공할 수 있다. | 권리·비용·품질을 확인하기 전에 큰 배치를 운영하게 된다. | 제외 |
| 여러 사이트를 구분 없이 AI로 수집 | 빠르게 많은 필드를 만들 수 있다. | 사이트별 이용 조건과 출처가 섞이고 오류·저작권 위험을 통제하기 어렵다. | 제외 |
| 전체는 `BASIC`, 일부는 `PARTIAL`·`ENRICHED`로 단계 보강 | 검색 범위를 넓히면서 상세 검수 비용을 실제 수요에 집중할 수 있다. | API와 화면이 누락값과 상태 차이를 처리해야 한다. | 선택 |

## 결정

아래 네 가지 방식을 팀 논의안으로 제안한다.

### 1. 범위와 상세 상태를 함께 관리한다

현재 2,000건을 첫 상세 제공 대상으로 삼는다. 기존 source manifest는 필드별 실제 출처와 이용 근거를 정정해 다시 승인하기 전까지 `provenance 재검증 대기`로 관리하며, 적재 가능한 입력으로 사용하지 않는다.

그다음에는 승인된 한 원본 스냅샷에서 보드게임과 확장으로 확인된 유효 항목을 `BASIC`으로 등록한다. 형식 오류, 중복 ID와 제외 대상은 식별자와 이유를 manifest에 남긴다.

게임별 `enrichment_status`는 다음과 같다.

- `BASIC`: ID, 원문 이름과 출처처럼 식별에 필요한 최소 필드만 허용·검증됨
- `PARTIAL`: 상세 필드 중 일부만 허용·검증됨
- `ENRICHED`: 버전이 지정된 상세 프로필의 필수 필드가 모두 허용·검증됨

상세 상태에는 판정에 사용한 프로필 버전이나 검증 배치를 연결한다. 프로필이 바뀌면 기존 `ENRICHED` 항목은 재검증한다. 상세 상태는 방 생성 가능 여부와 무관하며, 이는 [ADR-0018](0018-expansion-type-and-relations.md)의 `playability_type`으로 판단한다.

상세 보강 순서는 `인기 게임 → 국내 유통 게임 → 사용자 요청 게임`이다. 이는 배치 선정 기준이며 추천 점수가 아니다. 다음 배치 건수는 이전 배치의 오류율, 수집 시간, 처리 비용과 운영 성능을 보고 정한다.

### 2. 수집 전에 출처별 이용 범위와 provenance를 확인한다

| 출처 | 결정 |
| --- | --- |
| BGG | 서비스 요청과 분리된 오프라인 배치에서 원본을 보존하고 결정적 파서로만 처리한다. 공개 서비스는 Albam Mate DB와 API로 응답한다. |
| 공식 독립 출처 | 제작사, 한국 유통사와 공개 규칙서부터 허용 목록에 넣는다. 블로그·커뮤니티·리뷰 사이트는 이용 조건을 확인할 때까지 제외한다. |

BGG는 현재 허용된 원본 재현·표시와 출처 표기 범위에서만 사용한다. 별도 서면 근거가 생기기 전에는 다음 작업을 하지 않는다.

- 정규화·번역·요약·재작성과 파생 분류·점수·임베딩 생성
- AI/LLM이나 외부 처리자에게 원본 전송
- BGG 투표와 Albam Mate 사용자 투표의 합산·재계산
- 이미지 다운로드·변환·재호스팅

BGG 이미지·썸네일은 제공된 URL을 출처와 함께 직접 표시한다. 원본의 출처, 취득 시각, 요청 범위, 행 수와 SHA-256도 보존한다.

독립 출처는 `robots.txt`와 이용 조건을 모두 통과해야 한다. `robots.txt`는 수집 경로 규칙일 뿐 번역·재배포·AI 처리 권한이 아니다. AI 추출값은 공개 전 후보로만 저장하고, 근거가 없거나 출처가 충돌하면 격리한다.

source policy에는 허용 경로·필드·처리 방식·공개 및 상업적 사용 범위·확인 날짜·담당자·근거를 기록한다. 공개 필드에는 원본 위치, 수집 시각, 수집기·모델·규칙 버전, 원본 해시, 이용 근거와 검증 상태를 연결한다.

### 3. 의미가 다른 값은 합치지 않고, 미확정 값은 비워 둔다

| 정보 | 원칙 |
| --- | --- |
| 식별자·이름 | 내부 ID와 `bgg_id`, BGG 원문 이름과 공식 한국어 이름을 구분하고 각각 출처를 기록한다. |
| 인원 | 가능 인원(`min_players`, `max_players`)과 추천·최적 인원을 구분한다. BGG 투표와 Albam Mate 투표도 별도로 보존한다. |
| 난이도 | BGG Weight와 Albam Mate 자체 난이도를 구분한다. 자체 난이도의 축·계산식·필터는 후속 결정으로 둔다. |
| 분류·설명·임베딩 | 기존 `tag`의 의미는 유지한다. 다중 분류는 별도 관계로 설계하고, 설명·임베딩은 이용이 허용된 텍스트만 사용한다. |

[ADR-0023](../platform/0023-p0-flyway-baseline-reset-player-count-stages.md)의 추천·최적 인원 컬럼은 출처와 집계 계약이 승인될 때까지 `NULL`로 둔다. 설명, 다중 카테고리·메커니즘, 예상 시간, 출시 연도와 썸네일도 이용 범위와 상세 프로필이 정해진 뒤 보강한다.

값이 없으면 `NULL`을 사용한다. 빈 문자열, `정보 없음`, 이름을 반복한 설명처럼 실제 정보로 오해할 값을 채우지 않는다.

### 4. 검증과 적재를 하나의 실패 차단 게이트로 운영한다

현재 `prepare-game-catalog.mjs`는 2,000건용 P0 변환기로 유지한다. 전체 `BASIC` 카탈로그와 다중 출처 보강에는 새 입력·출력 계약을 둔다.

각 배치의 모든 행에서 스키마·필수값·범위·중복·대상 유형·출처·이용 근거·체크섬·출처 충돌을 자동 검증한다. 결정적 규칙으로 원문과 대조할 수 있는 사실 필드만 공개하고, 요약·난이도·단독 플레이 판단처럼 해석이 필요한 값은 승인 기준이 생길 때까지 후보로 둔다.

자동 검증 후에는 같은 source policy와 처리 버전을 사용한 배치에서 무작위 표본을 원문과 대조한다.

- 새 출처·정책·처리 버전: 20건
- 팀이 안정화됐다고 기록한 동일 조합: 배치마다 5건

manifest에는 정책·처리·상세 프로필 버전, 난수 seed, 표본 ID, 검수자와 결과를 남긴다. 표본에서 오류나 이용 범위 위반이 한 건이라도 나오면 전체 배치를 막고 같은 원본에서 다시 생성·검증한다.

manifest 미승인, 체크섬 불일치 또는 검증 실패 시 품질 보고서만 만들고 적재 산출물은 만들지 않는다. 통과한 배치는 안정적인 ID 매핑으로 `UPSERT`하며 기존 ID와 검증 이력을 유지한다. 새 스냅샷에 없다는 이유로 삭제하지 않고, 한 행이라도 적재에 실패하면 전체 반영을 롤백한다.

## 결과

- 얻는 것: 전체 게임의 발견 가능성을 넓히면서 상세 보강 비용은 실제 수요에 집중한다. 출처·후보·자체 값을 섞지 않는다.
- 감수할 비용: 화면과 API가 누락값과 상세 상태를 처리해야 하며, source policy와 필드별 provenance를 운영해야 한다.
- 후속 작업: 현재 2,000건의 provenance 재점검, BGG 추가 문의, 독립 출처 policy registry와 첫 배치 계약을 차례로 확정한다.

## 보류 및 재검토

- 지금 하지 않는 것: P0 계약 변경, 실행 중 BGG 호출, 이후 배치 건수 고정, 전체 상세 보강, 추천·최적 인원 계산, 자체 난이도·다중 분류·임베딩 설계, 미승인 번역·AI 처리·이미지 재호스팅
- 보류 이유: 이용 범위, 현재 자료의 provenance와 첫 배치 측정값이 아직 확정되지 않았다.
- 재검토 조건: BGG의 추가 서면 답변, 수익 모델 도입, provenance 재점검 완료, 첫 배치 결과 또는 새 출처 추가
