# ADR-0027: 게임 메커니즘을 검수된 내부 목록과 관계로 관리

- 상태: 승인됨
- 작성일: 2026-07-31
- 결정일: 2026-08-03
- 관련: [SEARCH-01 메커니즘 필터 후보](../../p1/search.md#search-01-게임-조건-검색), [ERD GAMES](../../ERD.md#games), [ADR-0015](0015-bgg-baseline-team-collected-game-list.md), [ADR-0019](0019-bgg-full-catalog-staged-enrichment.md), [출처 manifest](../../game-catalog/2026-07-24-source-manifest.draft.json)
- 대체 대상: 없음
- 후속 ADR: 없음

> 이 결정은 P1 필수 범위가 아니라 확장 후보다. 상위 P1 범위에 채택되기 전에는 API·ERD·구현 계약에 반영하지 않는다.

**결정 요약:** 사용자에게 익숙한 메커니즘 10~20개를 내부 목록으로 시작하고, 게임과 다대다 관계로 연결해 데이터 추가만으로 확장한다.

## 맥락

현재 `games`에는 메커니즘 필드나 관계가 없다. `Game.tag`는 팀이 만든 대표 표시 태그 한 개이며, 여러 메커니즘을 나타내는 공식 분류가 아니다.

외부 사이트마다 분류 이름과 범위가 다르다. 외부 이름이나 ID를 그대로 공개하면 출처가 바뀔 때 검색 계약도 함께 바뀌고, 문자열로 저장하면 중복·번역·별칭을 관리하기 어렵다.

이 후보의 목적은 외부 분류 전체를 재현하는 것이 아니라, 사용자가 익숙한 메커니즘으로 게임을 대략 좁히게 하는 것이다. 따라서 소수로 시작하되 기존 검색 계약을 바꾸지 않고 확장할 구조가 필요하다.

## 검토한 대안

| 대안 | 장점 | 비용·위험 | 판단 |
| --- | --- | --- | --- |
| 기존 `tag`를 재사용 | 스키마 변경이 작다. | 대표 태그와 다중 메커니즘의 의미가 섞인다. | 제외 |
| 메커니즘을 JSON·쉼표 문자열로 저장 | 처음 적재하기 쉽다. | 중복·별칭·무결성 관리와 관계 검색이 어렵다. | 제외 |
| 한 외부 출처의 분류 전체를 그대로 공개 | 초기 매핑이 단순하다. | 외부 ID와 분류 변경이 서비스 검색 계약에 직접 영향을 준다. | 제외 |
| 검수된 내부 목록과 게임 관계를 소수로 시작 | 검색 계약을 유지하면서 점진적으로 확장할 수 있다. | 초기 목록에 없는 세부 메커니즘은 검색할 수 없다. | 선택 |

## 결정

메커니즘은 Albam Mate의 검수된 내부 목록으로 관리하고 게임과 다대다 관계로 연결한다.

- 메커니즘은 안정적인 내부 ID·코드와 변경 가능한 표시명을 구분한다.
- 공개 목록은 애플리케이션 enum이 아니라 데이터로 관리한다.
- P1 표시명은 팀이 검수한 한국어 용어를 사용하며, 합의되지 않은 번역은 공개하지 않는다.
- 같은 게임과 메커니즘 조합은 하나만 허용한다.
- 기존 `Game.tag`는 현재 의미를 유지하고 메커니즘 저장소로 사용하지 않는다.

P1의 초기 공개 목록은 사용자에게 익숙하고 비교적 넓은 메커니즘 10~20개를 목표로 한다. 정확한 목록과 항목별 최소 연결 게임 수는 구현 전에 팀이 정한다.

새 메커니즘은 검수된 목록 행과 게임 관계를 추가하는 방식으로 확장한다. 기존 내부 ID와 코드의 의미를 바꾸지 않으며, 항목 추가 때문에 DB 스키마나 검색 파라미터를 변경하지 않는다.

게임-메커니즘 관계는 ADR-0015의 출처 원칙을 따른다. 실제 출처와 확인 시점·이용 근거·검수 결과를 다시 찾을 수 있어야 하며, 출처가 충돌하면 자동으로 확정하지 않는다. `웹 검색`, `AI 판단`만으로 관계를 만들지 않는다.

정확한 출처 후보와 적재 범위는 P1 검색 명세에서, 출처별 근거와 배치 기록은 manifest·적재 가이드에서 관리한다. 후보가 채택되면 다중 선택 방식과 요청 파라미터를 API 명세에 확정한다.

## 결과

- 얻는 것: 짧고 이해하기 쉬운 초기 필터를 제공하면서 항목과 관계 데이터 추가만으로 확장할 수 있다.
- 감수할 비용·위험: 초기 목록에 없는 세부 메커니즘은 검색할 수 없고, 새 항목과 관계를 계속 검수해야 한다.
- 후속 작업: 초기 목록·표시명·최소 연결 기준을 정하고 ERD, 출처 기록, 적재 도구와 관계 제약에 반영한다.

## 보류 및 재검토

- 지금 하지 않는 것: 외부 세부 분류 전체 공개, 테마 필터, 출처 미확인 자동 수집, AI 자동 분류, 전체 카탈로그 일괄 보강
- 보류 이유: P1은 검수된 소수 메커니즘으로 대략적인 검색만 제공한다.
- 다시 검토할 조건: 검색 요구나 이용 데이터에서 새 분류의 가치가 확인될 때, 전체 카탈로그 보강 범위가 승인될 때
