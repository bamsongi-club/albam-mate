# ADR (아키텍처 결정 기록)

이 폴더는 Albam Mate의 되돌리기 어렵거나 논쟁적인 결정을 기록한다. 루트 문서는 전체 ADR 목록을 담지 않고 작성 규칙과 도메인별 인덱스만 안내한다. 구현 명세는 이 인덱스에만 의존하지 않고, 작업에 필요한 ADR 파일을 직접 링크한다.

## 도메인 인덱스

| 도메인 | 다루는 결정 |
| --- | --- |
| [Platform](platform/README.md) | Java·Spring, 데이터베이스, 공통 식별자 등 백엔드 기반 |
| [Auth](auth/README.md) | 인증, 인가와 세션 보안 경계 |
| [Game](game/README.md) | 게임 목록의 출처, 적재와 검색 경계 |
| [Room](room/README.md) | 방 생명주기와 상태 전이 |
| [Participation](participation/README.md) | 참가 불변식, 정원과 동시성 |

## 작성 규칙

- 새 파일은 [0000-template.md](0000-template.md)를 복사해 결정이 속한 도메인 폴더에 만든다.
- 번호는 모든 도메인에서 공유하는 전역 4자리 일련번호다. 기존 정식 ADR 파일의 최댓값 다음 번호를 사용하고, 폴더가 달라도 같은 번호를 다시 사용하지 않는다.
- 후보 백로그에는 정식 ADR 번호를 부여하지 않는다. 실제 ADR 파일을 만들 때 번호를 배정한다.
- 파일명은 `NNNN-제목-요약.md` 형식을 사용한다. ADR을 다른 도메인으로 옮겨도 번호는 바꾸지 않는다.
- ADR 파일을 만들거나 제목·상태·결정일·검증 상태를 바꾸면 해당 도메인의 `README.md` 인덱스를 같은 변경에서 갱신한다. 루트에는 개별 ADR 목록을 추가하지 않는다.
- 도메인 인덱스의 `검증` 열에는 해당 ADR 검증 절의 상태 값을 그대로 옮긴다. 인덱스에서 새로 판정하지 않는다.
- 상태 값
    - `제안됨`: 논의 중이며 아직 확정되지 않음
    - `승인됨`: 팀이 채택함
    - `대체됨`: 승인된 결정을 이후 ADR이 대신함
    - `거부됨`: 승인 전에 논의했으나 채택하지 않음
    - `폐기됨`: 승인된 결정을 후속 ADR 없이 철회했거나 결정의 전제가 사라짐
- 검증 값
    - `미검증`: 결정대로 동작하는지 구현·측정으로 확인하지 않음
    - `검증됨`: 구현과 검증 근거로 결정대로 동작함을 확인함
- `검증` 절은 `상태`·`근거`·`미검증` 순서로 적는다.
- `근거`는 `구현`·`계약`·`테스트`·`CI`로 나누되, 확인된 증거가 있는 범주만 적는다. 확인된 근거가 하나도 없으면 `근거: 없음`으로 적고, 긴 단일 문장 대신 한 하위 bullet에 한 근거만 둔다.
- `미검증`에는 실행하지 못했거나 근거가 부족한 잔여 항목을 적고, 없으면 `없음`이라고 명시한다.
- `상태`가 `검증됨`이면 `미검증`은 반드시 `없음`이어야 한다. 잔여 미검증 항목이 하나라도 있으면 상태는 `미검증`이다.
- `상태`는 결정을 채택했는지, `검증`은 그 결정이 코드에서 확인됐는지를 나타낸다. `승인됨`을 구현·검증 완료로 읽지 않는다.
- `대체 대상`에는 이 ADR이 대신하는 기존 ADR, `후속 ADR`에는 이 ADR을 대신하는 새 ADR을 적는다.
- 결정 대체 시 새 ADR의 `대체 대상`에 옛 번호를 적고, 옛 ADR은 `대체됨`으로 바꾼 뒤 `후속 ADR`에 새 번호를 적는다.
- `작성일`은 ADR 파일을 처음 만든 날, `결정일`은 승인하거나 거부한 날이다. 제안 중이면 결정일에 `미정`을 적는다.
- 승인된 ADR의 결정 본문인 맥락·검토한 대안·결정·결과는 사후에 수정하지 않는다. 상태·대체 관계·검증 근거는 갱신할 수 있으며, 결정 자체가 바뀌면 새 ADR로 이전 결정을 대체한다.
- 승인됐거나 이후 대체된 ADR의 결정 본문에 남은 `현재`·`아직` 같은 시점 표현은 작성·결정 당시를 가리킨다. 현재 구현·검증 상태는 `검증` 절과 후속 ADR에서 확인한다.
- 회의·논의를 근거로 삼을 때는 브레인의 비공개 경로(`private/`, `meetings/`)를 링크하지 말고, 그 결론을 ADR의 맥락·대안에 문장으로 옮긴다. ADR은 외부 문서 없이도 결정 이유를 읽을 수 있게 자기완결적으로 쓴다.
