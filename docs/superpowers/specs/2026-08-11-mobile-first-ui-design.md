# 모바일 우선 UI 설계

## 목표

데스크톱 화면을 축소하는 대신, 767px 이하에서 터치·한손 조작·현재 모임 확인에 맞춘 별도 모바일 경험을 제공한다. 기존 해시 라우트와 API 계약은 유지하고, 데스크톱 정보 구조는 바꾸지 않는다.

## 확정된 UX

- 공유 시안의 아이보리 배경, 초록 상태색, 검정 핵심 CTA, 베이지 경계선, 둥근 카드와 고정 하단 탭을 모바일 시각 정본으로 쓴다.
- 하단 탭은 `홈`, `게임`, `내 모임`, `내정보` 네 개다.
- 전체 채팅 목록은 상단 말풍선 아이콘에서 열고, 특정 모임의 채팅은 내 모임 카드와 모임 상세의 채팅 버튼으로 바로 연다.
- 로그인 사용자의 홈 상단에는 가장 가까운 참여 모임을, 예정 모임이 없으면 모임 탐색·만들기 CTA를 보인다.
- 비로그인 홈은 게임·공개 모임 탐색을 우선한다.

## 접근안 비교

1. 기존 CSS의 폭·열 수만 줄인다. 변경량은 작지만 현재 데스크톱 헤더와 카드 우선순위가 그대로 남아 요청한 모바일 최적화가 되지 않는다.
2. 별도 모바일 라우트와 데이터 계층을 만든다. 완전히 독립적이지만 동일 API·상태·접근 제어를 중복해 회귀 위험이 크다.
3. 기존 해시 라우트와 API를 공유하고, 모바일 전용 셸·탭·홈 패널을 추가한다. 데스크톱은 유지하면서 모바일 정보 구조만 달라져 이 방식을 채택한다.

## 구조

- `frontend/src/mobile/MobileNavigation.jsx`는 모바일 상단 보조 동작과 네 개의 하단 탭을 렌더링한다. 현재 해시 route를 받아 활성 탭을 계산하고, 인증 상태에 맞는 `내 모임`·`내정보` 진입점을 선택한다.
- `frontend/src/mobile/MobileHomePanel.jsx`는 `api.getMyRooms`로 참여·개설 모임의 첫 100개를 함께 읽어 다음 내 모임을 보여 준다. 새 API나 서버 정렬 계약을 만들지 않고, 받은 모임 중 미래 시작 시각이 가장 이른 항목을 고른다.
- `frontend/src/main.jsx`는 기존 `Header`, `HomeView`, 해시 라우팅에 위 컴포넌트를 배선한다. 기존 데스크톱 DOM과 라우트 권한 검사는 유지한다.
- `frontend/src/styles.css`는 공용 색상 토큰을 시안 톤으로 통일하고, `max-width: 767px`에서 모바일 셸·카드·채팅·필터·안전 영역을 재배치한다.

## 화면 규칙

- 모바일 상단에는 현재 화면 맥락, 전체 채팅, 알림을 둔다. 프로필은 하단 탭으로 이동한다.
- 하단 탭은 `position: fixed`와 `env(safe-area-inset-bottom)`을 사용하며, 본문은 그 높이만큼 여백을 확보한다.
- 모든 주요 조작은 최소 44px 높이로 둔다. 검색·필터·게임 선택은 좁은 화면에서 전체 폭 또는 bottom-sheet 형태를 쓴다.
- 채팅은 모임 제목을 상단에 압축해 보이고, 대화 영역과 입력창을 세로 화면 안에 고정한다. 데스크톱의 좌측 정보 패널은 모바일에서 중복하지 않는다.
- 카드와 목록은 한 열로 흐르고, 게임 표지는 두 열까지 허용한다. 로딩·오류·비로그인 안내는 현재 문구와 접근 제어를 유지한다.

## 데이터와 범위

- 모든 HTTP 호출은 기존 `src/api.js`를 통해서만 수행한다.
- 홈의 내 모임 요약은 이미 제공 중인 `getMyRooms` 데이터를 재사용한다. 알림, 채팅, 참가·취소, 게임 검색의 서버 동작은 변경하지 않는다.
- 데스크톱에서는 기존 헤더·본문 구조를 유지한다. 공용 색·버튼·카드 토큰만 모바일 시안과 일치시키며, 별도의 데스크톱 리디자인은 이번 범위에서 제외한다.

## 검증

- 모바일 탭의 활성 상태·인증별 링크와 홈의 예정/빈 상태를 React Testing Library로 검증한다.
- 채팅·알림·게임 선택의 기존 접근 경로가 그대로 렌더링되는지 관련 테스트를 단일 worker로 실행한다.
- Vite production build와 390px·768px·데스크톱 폭에서 실제 화면을 확인한다.
- 기준 `develop`의 병렬 Vitest 전체 실행은 worker 기동 timeout으로 31개가 실패했다. 동일 환경에서 `--maxWorkers=1` 단일 테스트는 통과했으므로, 이번 변경의 TDD와 회귀 검증은 단일 worker로 재현 가능한 명령을 사용한다.
