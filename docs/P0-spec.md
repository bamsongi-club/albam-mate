# 알밤메이트 1차 MVP 기획서 (수정안)

> 본 문서는 알밤메이트의 핵심 유저 흐름을 빠르게 구현하고 검증하기 위한 1차 MVP 범위를 정의한다.
>
> 1차 MVP에서는 정상적인 입력과 사용 순서에 따른 성공 흐름을 우선 구현한다. 복합 예외 상황, 운영 제재, 상세 취소·수정 정책, 동시성 경쟁 상황 등은 1차 구현 완료 후 별도 정책으로 구체화한다.
>
> 세부 요청·응답 필드, 오류 코드, 데이터베이스 구조, 인증 방식 등은 별도의 API 명세서와 기술 설계서에서 관리한다.

## 1. 서비스 개요

### 1.1 서비스 비전

알밤메이트는 유저가 게임 정보와 모임 조건을 참고하여 보드게임 모임을 찾고, 일반 유저 또는 룰마스터가 만든 모임에 참가할 수 있도록 돕는 보드게임 플레이 매칭 플랫폼을 지향한다.

### 1.2 1차 MVP 정의

1차 MVP에서는 홍대에서 열리는 오프라인 보드게임 세션을 대상으로 다음 경험을 제공한다.

- `게임부터 찾기`와 `사람부터 만나기` 두 가지 탐색 방식 제공
- 게임 목록 조회
- 게임 중심 세션 목록 탐색
- 사람 중심 세션 목록 탐색
- 게임 중심 또는 사람 중심 세션 생성
- 세션의 일시, 장소, 정원, 경험 수준, 룰마스터 진행 여부 확인
- 남은 자리에 선착순 참가
- 내가 참가하거나 개설한 세션 확인
- 세션 상세에서 참가자 확인

### 1.3 해결하려는 문제와 검증 가설

알밤메이트는 보드게임을 하고 싶은 유저가 게임·참가자·룰마스터를 빠르게 찾아 실제 플레이 모임을 성립시킬 수 있도록 돕는다. 원하는 시간과 장소에 함께할 사람, 플레이할 게임, 규칙을 설명할 사람이 동시에 맞지 않아 모임이 성립되지 않는 문제를 해결한다.

> 게임, 일시, 장소, 경험 수준, 룰마스터 진행 여부와 남은 자리를 확인할 수 있다면, 함께할 사람이 없는 유저도 보드게임 세션 참가를 완료할 수 있다.

### 1.4 대상 유저와 역할

대상 유저는 함께 갈 일행을 구하기 어려운 보드게임 카페 방문 유저, 새로운 게임을 가볍게 경험하고 싶은 초보·라이트 유저, 자신이 아는 게임을 다른 유저에게 설명하고 진행하고 싶은 유저다.

> 핵심 페르소나는 오늘이나 이번 주에 보드게임을 하고 싶지만, 함께할 사람을 구하고 게임을 선택하며 규칙을 익히는 과정이 부담스러운 초보·라이트 유저다.

한 명의 유저는 세션에 따라 여러 역할을 수행할 수 있다.

- 참가자: 게임 또는 사람 중심 세션을 탐색하고 참가·취소하며, 참가한 세션을 확인한다.
- 세션 개설자: 세션을 생성·수정·취소·종료하고 참가자를 확인한다.
- 룰마스터: 세션에서 규칙 설명과 게임 진행을 담당한다고 직접 표시하는 개설자 역할이다. MVP에서는 별도의 유저 유형이나 인증 자격이 아니다.

## 2. 1차 MVP 구현 원칙

### 2.1 성공 흐름 우선

1차 구현에서는 다음 세 가지 유저 흐름을 처음부터 끝까지 연결하는 것을 가장 중요한 목표로 한다.

1. 게임부터 찾고 세션에 참가하는 흐름
2. 사람 중심 세션을 찾고 참가하는 흐름
3. 개설자가 세션을 만들고 참가자를 확인하는 흐름

### 2.2 원칙과 운영 규칙의 분리

1차 구현에서는 정상적인 입력과 일반적인 사용 순서에 따른 성공 흐름을 우선한다. 생성·참가·정원·상태에 관한 실제 운영 규칙은 7절에서 단일 기준으로 관리한다.

### 2.3 복합 예외는 후속 보완

복합 예외와 MVP 이후 정책의 상세 기준은 [1차 구현 이후 정책 보완 항목](./MVP_POLICY_BACKLOG.md)에서 관리한다.

- 세션 수정
- 세션 취소
- 세션 종료
- 세션 참가
- 참가 취소
- 내 모임 조회

## 4. 화면 흐름과 표시 기준

게임 중심과 사람 중심은 서버에서 조회하는 카테고리 목록이 아니라, 유저가 서비스를 이용하는 두 가지 고정 탐색 방식이다.

MVP에서는 홈 화면에 다음 두 개의 진입 버튼을 고정으로 제공한다.

- `게임부터 찾기`
- `사람부터 만나기`

### 4.1 게임부터 찾기

플레이하고 싶은 게임을 먼저 선택한 뒤, 해당 게임으로 개설된 세션을 찾는 방식이다.

```text
게임부터 찾기
→ 게임 목록·검색
→ 게임 카드 선택
→ 게임 상세 화면
→ 선택한 게임의 게임 중심 세션 목록
→ 세션 상세 조회
→ 회원가입 또는 로그인
→ 세션 참가
→ 내 모임에서 참가한 세션 확인
```

#### 게임 목록 화면 기준

게임 목록의 카드 하나는 세션이 아니라 게임을 나타낸다.

각 카드에는 다음 정보를 표시할 수 있다.

- 게임명
- 영문명
- 대표 이미지
- 권장 인원
- 예상 플레이 시간
- 난이도 표시
- 예정 모임 수

`예정 모임 수`는 해당 게임으로 생성된 미래 시점의 게임 중심 세션 중 `CANCELED`, `FINISHED` 상태가 아닌 세션의 수다.

게임 카드를 선택하면 게임 상세 화면으로 이동한다. 게임 상세에서는 게임 카드 수준의 기본 정보를 확인하고, 해당 게임의 게임 중심 세션 목록 화면으로 이동해 세션을 확인하거나 해당 게임으로 모임을 생성할 수 있다.

### 4.2 사람부터 만나기

플레이할 게임을 먼저 선택하지 않고, 친목과 만남을 우선하는 사람 중심 세션을 탐색하는 방식이다.

```text
사람부터 만나기
→ 사람 중심 세션 목록
→ 세션 상세 조회
→ 회원가입 또는 로그인
→ 세션 참가
→ 내 모임에서 참가한 세션 확인
```

### 4.3 세션 만들기

```text
회원가입 또는 로그인
→ 게임 중심 또는 사람 중심 세션 선택
→ 게임 중심인 경우 게임 목록 검색 및 게임 선택
→ 모임 제목, 경험 수준, 정원, 일시, 장소, 한 줄 소개(선택) 입력
→ 룰마스터 진행 여부 선택
→ 세션 생성
→ 내 모임에서 개설한 세션 확인
→ 세션 상세에서 참가자 목록 확인
→ 모임 진행 후 세션 종료 처리
```

### 4.4 세션 목록 화면 구성

게임 중심과 사람 중심의 목록 화면은 다르게 표현할 수 있지만, 조회 대상은 모두 `Session`이다.

프론트엔드는 세션 유형에 따라 목록 카드의 표시 항목과 레이아웃을 다르게 구성할 수 있다.

### 4.5 세션 상세 화면 구성

게임 중심과 사람 중심 세션 모두 세션 상세 화면에서 확인한다.

세션 상세 화면의 구성은 `type`에 따라 다르게 표시할 수 있다.

#### 공통 표시 정보

- 세션 유형
- 상태
- 일시
- 지역(홍대)
- 장소
- 정원
- 경험 수준
- 개설자
- 룰마스터 진행 여부
- 참가자 목록
- 남은 좌석 수

#### 게임 중심 세션

- 선택된 게임 정보가 반드시 포함된다.
- 게임명, 대표 이미지 등 최소 정보만 표시한다.

#### 사람 중심 세션

- 게임이 아직 정해지지 않았다면 게임 정보는 `null`이다.
- 화면에는 `게임 미정`으로 표시할 수 있다.
- 게임이 선택되어 있다면 선택된 게임의 최소 정보를 표시할 수 있다.

## 5. 핵심 개념과 세션 구성

### 5.1 유저(User)

서비스에 가입하여 세션을 만들거나 참가할 수 있는 유저이다.

MVP에서는 이메일, 비밀번호, 닉네임 등 최소 프로필 정보를 사용한다.

### 5.2 게임(Game)

게임은 세션에서 플레이할 보드게임을 선택하기 위한 참조 데이터다.

게임은 알밤메이트 MVP의 핵심 관리 도메인이 아니며, 운영자가 사전에 입력한 더미 또는 초기 데이터를 사용한다.

게임 데이터는 다음 네 곳에서 사용한다.

1. `게임부터 찾기` 화면의 게임 목록
2. 게임 상세 화면
3. 게임 중심 세션 생성 시 게임 선택
4. 세션 상세의 선택 게임 정보 표시

MVP에서는 다음 기능을 제공하지 않는다.

- 유저의 게임 등록
- 유저의 게임 수정·삭제
- 게임별 리뷰
- 게임별 룰마스터 목록 조회

게임 목록에서 사용할 수 있는 필드는 다음과 같다.

- 게임 ID
- 게임명
- 게임 영문명
- 대표 이미지
- 권장 최소·최대 인원
- 예상 플레이 시간
- 난이도 표시
- 예정 모임 수

### 5.3 세션(Session)

홍대 내 특정 일시와 장소에서 진행되는 보드게임 모임 단위다.

세션은 다음 정보를 가진다.

- 세션 유형
- 모임 제목
- 한 줄 소개(선택)
- 선택 게임
- 경험 수준
- 룰마스터 진행 여부
- 정원
- 시작 일시
- 지역(홍대)
- 장소
- 개설자
- 상태

### 5.4 세션 유형(SessionType)

MVP에서는 다음 두 가지 세션 유형을 제공한다.

- `GAME_FOCUSED`: 게임 중심 세션
- `PERSON_FOCUSED`: 사람 중심 세션

세션 유형은 세션이 가지는 유형값이며, 생성 시 선택한다.

#### 게임 중심 세션

- 게임 카탈로그에서 게임 1개를 반드시 선택한다.
- 선택한 게임을 함께 플레이할 참가자를 모집한다.
- `gameId`는 필수다.
- 게임 목록의 게임 카드를 선택하면 해당 게임의 게임 중심 세션 목록을 조회한다.

#### 사람 중심 세션

- 친목과 네트워킹을 우선하는 세션이다.
- 플레이할 게임은 현장에서 결정할 수 있다.
- 게임 선택은 선택 사항이다.
- 게임이 정해지지 않은 경우 `게임 미정`으로 표시한다.

### 5.5 참가와 정원

#### 정원(Capacity)

정원 입력값은 개설자를 제외한 모집 인원이다. 세션 생성 시 개설자는 자동으로 참가자 목록에 포함된다.

예를 들어 개설자가 정원 8명을 설정하고 세션을 생성한다면,

- 전체 정원: 9명(개설자 1명 + 모집 인원 8명)
- 세션 상세에는 개설자를 포함한 전체 정원과 현재 참가자 수를 표시한다.
- 참가자 목록에는 개설자가 포함된다.
- 남은 좌석은 전체 정원에서 현재 참가자 수를 뺀 값이다.

정원의 세부 최소·최대 범위는 1차 구현 이후 확정한다.

#### 참가(Participation)

유저가 특정 세션에 참가한 관계를 의미한다.

- 참가 성공 시 별도의 승인 없이 즉시 참가자로 등록된다.
- 동일 유저는 같은 세션에 활성 참가 상태를 하나만 가진다.
- 참가를 취소한 경우, 시작 시각 전 세션이 `RECRUITING` 상태이고 남은 좌석이 있을 때 다시 참가할 수 있다.

### 5.6 세션 속성 및 상태

#### 경험 수준(ParticipantLevel)

경험 수준은 개설자가 해당 세션에 어떤 수준의 유저를 권장하는지 표시하는 안내 정보다.

MVP에서는 다음과 같은 값을 사용할 수 있다.

- `ALL_LEVELS`: 경험 무관
- `BEGINNER_WELCOME`: 초보자 환영
- `EXPERIENCED_PREFERRED`: 경험자 위주

해당 값은 안내 목적으로만 사용하며, 서버가 참가자의 실제 경험 수준을 검사하거나 참가를 차단하지 않는다.

경험 수준을 이용한 검색·필터는 [향후 기능 범위](./FUTURE_FEATURES.md)에서 검토한다.

#### 룰마스터 진행 여부

세션 개설자가 해당 세션에서 규칙 설명과 게임 진행을 담당하겠다고 직접 표시한 것을 의미한다.

- 개설자의 자기신고 정보다.
- 플랫폼은 룰 숙련도나 자격을 검증하지 않는다.
- 게임 중심과 사람 중심 세션 모두 설정할 수 있다.

#### 세션 상태(SessionStatus)

MVP에서는 다음 상태를 사용한다.

- `RECRUITING`: 모집 중이며, 시작 시각 전 참가할 수 있는 상태
- `CLOSED`: 정원이 찼거나 시작 시각에 도달하여 모집이 종료된 상태
- `CANCELED`: 개설자가 취소한 상태
- `FINISHED`: 개설자가 종료 처리했거나 시스템이 자동 종료 처리한 상태

세션은 생성 직후 `RECRUITING` 상태로 생성된다. 상태 전이는 다음의 정상 흐름만 MVP에서 다룬다.

- 모집 정원이 모두 차거나 시작 시각에 도달하면 `RECRUITING`에서 `CLOSED`로 전환한다.
- 시작 시각 전 참가 취소로 좌석이 생기면 `CLOSED`에서 `RECRUITING`으로 되돌아간다.
- 개설자는 `RECRUITING` 또는 `CLOSED` 상태의 세션을 `CANCELED`로 변경할 수 있다.
- 개설자는 모임 후 `CLOSED` 상태의 세션을 `FINISHED`로 변경할 수 있다.
- 시작 시각으로부터 24시간이 지났을 때 세션이 여전히 `CLOSED`이면 시스템이 `FINISHED`로 변경한다.
- `CANCELED`, `FINISHED` 상태에서는 수정하거나 참가할 수 없다.

## 6. 1차 MVP API

1차 MVP에서는 총 15개의 API를 제공한다.

| #  | API | 메서드/경로 | 인증 필요 | 정상 성공 기준 |
|----|---|---|---|---|
| 1  | 회원가입 | `POST /api/auth/signup` | N | 신규 유저 생성 |
| 2  | 로그인 | `POST /api/auth/login` | N | 인증 토큰 발급 |
| 3  | 내 프로필 조회 | `GET /api/users/me` | Y | 본인 프로필 조회 |
| 4  | 내 프로필 수정 | `PATCH /api/users/me` | Y | 본인 프로필 수정 |
| 5  | 게임 목록·검색 | `GET /api/games?keyword=...&page=...&size=...` | N | 게임 목록 조회 및 게임명 검색 |
| 6  | 게임 상세 조회 | `GET /api/games/{gameId}` | N | 게임 상세 조회 |
| 7  | 세션 생성 | `POST /api/sessions` | Y | 게임 중심 또는 사람 중심 세션 생성 |
| 8  | 세션 목록 조회 | `GET /api/sessions` | N | 유형별 세션 목록 조회(`GAME_FOCUSED`: `gameId` 필수, `PERSON_FOCUSED`: `gameId` 생략) |
| 9  | 세션 상세 조회 | `GET /api/sessions/{sessionId}` | N | 세션 정보와 참가자 목록 조회 |
| 10 | 세션 수정 | `PATCH /api/sessions/{sessionId}` | Y | 개설자가 세션 정보 수정 |
| 11 | 세션 취소 | `DELETE /api/sessions/{sessionId}` | Y | 세션을 `CANCELED` 상태로 변경 |
| 12 | 세션 종료 | `PATCH /api/sessions/{sessionId}/status` | Y | 세션을 `FINISHED` 상태로 변경 |
| 13 | 세션 참가 | `POST /api/sessions/{sessionId}/participants` | Y | 유저를 참가자로 등록 |
| 14 | 참가 취소 | `DELETE /api/sessions/{sessionId}/participants/me` | Y | 본인의 참가 취소 |
| 15 | 내 모임 조회 | `GET /api/users/me/sessions?role=all\|joined\|hosted` | Y | `role` 기준 본인의 참여·개설 세션 이력 조회 |

### 6.1 목록 조회 경로와 파라미터

게임 목록은 다음 경로로 조회한다.

```http
GET /api/games?keyword=...&page=...&size=...
```

- `keyword`는 게임명을 대상으로 하는 MVP의 기본 검색이다.

세션 목록은 다음 경로로 조회한다.

```http
GET /api/sessions?type=GAME_FOCUSED&gameId=...&page=...&size=...
GET /api/sessions?type=PERSON_FOCUSED&page=...&size=...
```

- `type`은 필수 파라미터다.
- `type=GAME_FOCUSED` 목록은 `gameId`가 필수이며, 선택한 게임의 게임 중심 세션 목록을 조회한다.
- `type=PERSON_FOCUSED` 목록은 `gameId`를 생략해야 하며, 값이 전달되면 잘못된 파라미터 조합으로 오류 처리한다.
- `type`, `gameId`는 탐색 경로를 위한 목록 구분값이며, 세션 조건 필터가 아니다.
- 목록 조회에는 페이지네이션을 적용한다.
- `CANCELED`와 `FINISHED` 상태의 세션은 목록 조회에서 제외한다.
- 게임 목록에서는 게임명 기본 키워드 검색만 제공한다.
- 세션 상태, 인원, 예상 플레이 시간, 난이도, 경험 수준, 태그 기반 필터는 1차 MVP에서 제공하지 않는다.

내 모임은 다음 기준으로 조회한다.

- `role=joined`: 본인이 개설하지 않았지만 참가한 세션
- `role=hosted`: 본인이 개설한 세션
- `role=all`: `joined`와 `hosted`의 중복 없는 합집합

## 7. 1차 MVP 운영 규칙

### 7.1 프로필

- 유저는 본인의 프로필을 조회하고 수정할 수 있다.
- 세션 개설자와 참가자 표시를 위해 닉네임을 사용한다.
- 타 유저 공개 프로필 조회는 MVP에서 제공하지 않는다.
- 프로필 이미지의 등록·변경은 MVP에서 제공하지 않으며, [향후 기능 범위](./FUTURE_FEATURES.md)에서 검토한다.

### 7.2 게임

- 게임 데이터는 운영자가 사전에 더미 또는 초기 데이터로 입력한다.
- 비로그인 유저도 게임 목록과 검색 결과를 조회할 수 있다.
- 유저의 신규 게임 등록·수정·삭제는 지원하지 않는다.

### 7.3 세션 생성

- 유저는 세션을 생성할 수 있다.
- 게임 중심 세션은 게임을 반드시 선택한다.
- 사람 중심 세션의 게임 선택은 선택 사항이다.
- 세션 시작 시각은 생성 시점보다 미래여야 한다.
- MVP 서비스 제공 지역은 홍대로 고정하며, 생성 시 지역은 입력받지 않고 장소만 입력한다
- 개설자가 입력하는 정원은 개설자를 제외한 모집 인원이다.
- 세션 생성 직후 상태는 `RECRUITING`이다.
- 개설자는 생성 시 자동으로 참가자 목록에 포함된다.
- 룰마스터 진행 여부는 개설자가 직접 선택한다.

### 7.4 참가

- 참가 신청은 선착순 즉시 확정 방식이다.
- 개설자의 별도 승인 과정은 없다.
- 시작 시각 전 `RECRUITING` 상태의 세션에만 참가할 수 있다.
- `CANCELED`, `FINISHED` 상태의 세션에는 참가할 수 없다.
- 동일 유저는 같은 세션에 활성 참가 상태를 하나만 가진다.
- 동일 유저는 다른 세션에 추가 참가할 수 있다.
- 동일 시간대 다른 세션 참가 제한의 상세 기준은 [1차 구현 이후 정책 보완 항목](./MVP_POLICY_BACKLOG.md)에서 관리한다.

### 7.5 정원 및 모집 상태

- 세션을 생성할 때 개설자를 제외한 정원을 입력하며, 개설자는 자동으로 참가자 목록에 포함된다.
- 개설자를 포함한 현재 참가자 수가 전체 정원에 도달하면 상태를 `CLOSED`로 변경한다.
- `CLOSED` 상태에서는 추가 참가를 받지 않는다.
- 시작 시각 전 참가 취소로 자리가 생기면 `RECRUITING`으로 되돌린다.
- 시작 시각 이후에는 참가 취소로 자리가 생겨도 `RECRUITING`으로 되돌리지 않는다.
- 1차 구현에서는 일반적인 순차 요청을 기준으로 정원 초과를 방지한다.
- 다수 유저의 동시 참가 요청에 대한 경쟁 조건 처리는 [1차 구현 이후 정책 보완 항목](./MVP_POLICY_BACKLOG.md)에서 관리한다.

### 7.6 수정

- 개설자를 제외한 참가자가 없으면 생성 시 설정한 모든 필드를 수정할 수 있다.
- 개설자를 제외한 참가자가 한 명 이상이면 세션 수정은 1차 MVP에서 제공하지 않는다.
- 참가자가 있는 세션의 상세 수정 정책은 [1차 구현 이후 정책 보완 항목](./MVP_POLICY_BACKLOG.md)에서 관리한다.

### 7.7 참가 취소

- 개설자가 아닌 참가자는 자신의 참가를 취소할 수 있다.
- 개설자는 참가 취소 API를 사용할 수 없다.
- 취소 후 시작 시각 전 세션이 `RECRUITING` 상태이고 자리가 있다면 다시 참가할 수 있다.
- 참가 취소 가능 시각과 마감 기준은 [1차 구현 이후 정책 보완 항목](./MVP_POLICY_BACKLOG.md)에서 관리한다.

### 7.8 세션 취소

- 개설자는 `RECRUITING` 또는 `CLOSED` 상태의 자신이 만든 세션을 취소할 수 있다.
- 개설자가 자신의 모임을 그만두려면 세션 자체를 취소한다.
- 세션 취소는 데이터를 물리적으로 삭제하지 않고 `CANCELED` 상태로 변경한다.
- 세션 취소 시 참가자 알림은 1차 MVP 범위에서 제외한다.

> 팀 논의 필요: 개설자가 세션을 유지한 채 참가만 취소할 수 있도록 허용할지는 1차 구현 이후 정책으로 검토한다.

### 7.9 세션 종료

- 개설자는 모임 후 `CLOSED` 상태의 세션을 `FINISHED` 상태로 변경할 수 있다.
- 시작 시각으로부터 24시간이 지났을 때 세션이 여전히 `CLOSED`이면 시스템이 `FINISHED` 상태로 변경한다.

### 7.10 조회

- 비로그인 유저도 게임 목록·검색·상세를 조회할 수 있다.
- 비로그인 유저도 세션 목록·상세를 조회할 수 있다. 일반 세션 목록에서는 `CANCELED`, `FINISHED` 상태를 제외한다.
- 비로그인 유저도 취소·종료 세션의 직접 상세 URL을 조회할 수 있다.
- 참가와 세션 생성은 로그인 후 사용할 수 있다.
- 세션 상세 응답에는 참가자 목록이 포함된다.
- 비로그인 유저에게는 참가자 닉네임을 공개하고 프로필 이미지는 비공개한다.
- 내 모임 이력은 해당 유저 본인만 조회할 수 있으며, 본인이 참가하거나 개설한 `CANCELED`, `FINISHED` 세션도 포함한다.
- 이메일과 로그인 식별 정보는 다른 유저에게 노출하지 않는다.
