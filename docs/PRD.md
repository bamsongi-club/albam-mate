## 1. 배경과 문제

보드게임 사용자는 원하는 시간에 함께할 사람·게임·규칙 설명 가능 여부를 맞추기 어렵고, 모집 정보가 게임·시간·장소·인원·진행으로 흩어져 실제 플레이로 이어지지 못하는 경우가 많다.

특히 초보·라이트 유저는 다음 장벽을 느낀다.

- 함께 갈 일행이 없거나 시간·장소를 맞추기 어렵다.
- 어떤 게임을 골라야 할지, 자신에게 너무 어렵지는 않을지 판단하기 어렵다.
- 규칙을 설명하거나 진행해 줄 사람이 있는지 알기 어렵다.

알밤메이트의 전체 목표는 신규 가입자 수가 아니라 **게임·참가자·진행 정보가 맞는 실제 모임이 성립하고 완료되는 비율**을 높이는 것이다.

## 2. 제품 비전과 경계

### 제품 비전

알밤메이트는 게임·사람 기준으로 모임을 찾고 만들며, 필요하면 룰마스터의 진행 정보·신뢰 이력을 참고해 오프라인·온라인 플레이까지 잇는 보드게임 방 플랫폼이다.

### 장기 제품 목표

1. 사용자가 게임명, 인원, 시간, 복잡도, 테마·메커니즘 등으로 자신에게 맞는 게임과 방을 찾는다.
2. 사용자가 게임 중심 또는 사람 중심 모임을 만들고, 다른 사용자가 조건을 확인한 뒤 안전하게 참여한다.
3. 룰마스터의 진행 가능 게임·이력·후기를 참고해 초보도 참여 판단을 할 수 있다.
4. 온라인 방에서는 현재 `ACTIVE` 참가자 전용 조율 공간과 외부 플레이 플랫폼 연결로 실제 플레이를 지원한다.
5. 완료·참석·후기 데이터가 다음 모임의 신뢰와 선택을 돕는다.

### 제품 경계

- 포인트 충전·지급·차감·반환 참여 정책은 후속 후보이며 도입 여부·금액·노쇼 기준은 미정이다. 감사비·보드게임 판매·주문·배송은 범위 밖이다.
- 인앱 보드게임 엔진과 음성·화상 통화는 제공하지 않으며, 온라인 플레이는 외부 플랫폼 연동·조율 도구에 집중한다.
- P0 공개 방 정보는 참여 판단에 필요한 범위로 제한하며, 사용자 ID·참가자 목록·정확한 장소·이메일·인증 정보는 다른 사용자에게 노출하지 않는다. 정확한 장소와 참가자 목록은 주최자와 현재 `ACTIVE` 참가자만 조회한다.
- P1 채팅은 메시지를 저장한 서버와 사용자의 실시간 연결을 보유한 서버가 달라도 동작해야 한다. PostgreSQL 메시지를 정본으로 유지하고 Redis는 공용 세션·실시간 신호·전송 제한에만 사용한다.
- 초기 오프라인 검증의 지역·장소 정책은 [방 명세](archive/p0/room.md)에서 확인할 수 있다. 지역 확장은 초기 검증 뒤 후속 후보로 논의한다.

## 3. 사용자와 역할

### 참가자

게임 또는 사람을 기준으로 모임을 탐색하고, 모임 정보를 확인한 뒤 참가하는 사용자다.

### 주최자

방을 만들고 모임 운영에 필요한 변경·취소·종료를 담당하는 사용자다.

### 룰마스터

룰마스터는 방에서 규칙 설명과 게임 진행을 돕는 사용자다. P0의 룰마스터 표시와 권한 정책은 [방 명세](archive/p0/room.md)에서 확인할 수 있다.

후속 단계에서는 사용자가 진행 가능 게임, 초보자 진행 가능 여부, 설명 언어·시간 등을 등록하고 완료 이력·후기를 쌓는 룰마스터 프로필을 제공할 수 있다.

## 4. 전체 제품 경험

### P0: 방 성립 경험

P0의 전체 사용자 흐름은 [P0-spec](archive/p0/P0-spec.md#핵심-사용자-흐름), 게임·방 화면 표시 기준은 [게임 목록 명세](archive/p0/game-catalog.md)와 [방 명세](archive/p0/room.md)에서 확인할 수 있다.

### P1: 로그인·탐색·알림·조율과 정합성 검증

P1은 Google·Naver·Kakao 로그인과 명시적 계정 연결, 프로필 이미지 등록·변경, 조건 검색과 사용자별 해 본 게임 표시·취소·필터, 전체·최근 7일 인기 게임 랭킹, 선착순 대기열·자동 승격, 신뢰성 있는 앱 내 알림, 다중 인스턴스에서도 동작하는 기존 오프라인 방 채팅, 제한된 ROOM 상태 자동 전환과 현재 낙관적 락 비용 측정을 추가했다. 전체 범위와 종료 상태는 [P1 아카이브](archive/p1/README.md)에서 확인한다.

### P2: AI 상호작용·의도 검색·실시간 매칭·운영 관측

P2는 AI 챗봇, 게임 의미 기반 검색, 실시간 매칭과 운영 관측을 독립 기능 명세로 정의하고 P1 계약 위에 통합한다. 공통 범위와 문서·통합 원칙은 [P2-spec](P2-spec.md), 기능별 준비·구현·배포·실측 상태는 [P2 기능 문서](p2/README.md)를 따른다. 팀원별 기능 ID·데이터·권한·실패·복구·품질 기준은 각 상세 명세와 필요한 ADR을 승인하기 전까지 추측하지 않는다.

### P2 이후 확장 경험 (도입 차수 미정)

~~~text
조건 검색으로 게임·방·룰마스터 후보 탐색
→ 진행 가능 게임·후기·이력 확인
→ 오프라인 또는 온라인 방 참여
→ 온라인이면 현재 `ACTIVE` 참가자 전용 조율 공간과 외부 플랫폼 접속
→ 플레이 완료·후기·참석 이력 반영
→ 다음 모임 선택에 신뢰 정보 활용
~~~

## 5. 기능 요구사항

### P0 1차 MVP

P0의 포함·제외 범위와 API 목록은 [P0-spec](archive/p0/P0-spec.md)에서, 기능별 규칙은 [세부 명세](archive/p0/P0-spec.md#관련-문서), 완료 조건은 [구현 완료 기준](archive/p0/P0-spec.md#구현-완료-기준)에서 확인할 수 있다.

### P1 2차 MVP

P1의 필수 범위·조건부 후속·기능별 완료 조건과 종료 상태는 [P1 아카이브](archive/p1/README.md)를 따른다.

### P2 3차 MVP

P2의 공통 범위와 통합 완료 기준은 [P2-spec](P2-spec.md), 기능별 상세 계약과 상태는 [P2 기능 문서](p2/README.md)를 따른다. P2 문서에 방향이 적혀 있어도 필요한 API·ERD·아키텍처·ADR과 구현·검증·배포·실측 상태가 따로 충족되기 전에는 제공 기능으로 판단하지 않는다.

### 후속 기능 후보 (도입 차수 미정)

아래 항목은 현재 P2 필수 범위에 채택되지 않은 후속 후보다.

- **조건 검색 확장:** P1 인원·시간·난이도·방 조건 검색 뒤 지역, 스타일 태그, 카테고리·BGG Weight를 검토한다.
- **사람 중심 조건 보강:** 사람 중심 방은 게임 없이도 유지하며, 원하는 태그·카테고리·난이도는 선택 정보로 저장·검색할 수 있다. 필수 조건으로 강제하지 않는다.
- **룰마스터 프로필:** 룰마스터 모드 ON/OFF, 진행 가능 게임, 초보자 진행 정보, 이력·후기 표시를 제공한다.
- **후기와 신뢰:** 완료된 방의 `ACTIVE` 참가 이력이 있는 사용자가 후기를 작성·수정·삭제하고, 참석·취소·진행 이력을 신뢰 정보로 활용한다.
- **탐색 보조 확장:** P1 인기 게임 랭킹 뒤 실시간 인기 검색어와 오늘 바로 참여 가능한 모임을 검토한다.
- **온라인 방:** 온라인 모임을 만들고, 현재 `ACTIVE` 참가자만 접속 정보와 조율 공간에 접근하게 한다.
- **온라인 플레이룸:** P1 오프라인 방 채팅 뒤 온라인 전용 플레이룸과 외부 플랫폼 링크 공유를 검토한다.
- **게임 정보 보강:** AI 핵심 규칙 요약, 규칙 설명 영상 연결을 제공한다.
- **추천:** 유사 게임 추천과 개인화 추천 알고리즘을 검토한다.
- **내 후기:** 내가 작성한 후기 목록을 조회한다.
- **운영·안전:** 사용자 신고·차단, 노쇼 신고와 이의제기 흐름을 제공한다.
- **포인트 정책:** 포인트 충전, 가입 보너스, 방 생성·참가 차감, 방 종료 뒤 반환을 검토한다. 기준 금액 `1,000`과 노쇼 미반환은 정책 후보일 뿐 확정 규칙이 아니다.
- **알림 확장:** P1 앱 내 방·참가 알림 뒤 후기 알림, 이메일·모바일 푸시와 사용자별 수신 정책을 검토한다.

## 7. P2와 후속 화면·정보 구조

- P1 유지 기능: Google·Naver·Kakao 로그인·계정 연결, 프로필 이미지 등록·변경, 게임·방 조건 필터, ROOM별 대기 신청·현재 상태, 앱 내 알림함·미확인 개수, 기존 오프라인 방 채팅, 인기 게임 랭킹
- P2: AI 챗봇, 게임 의미 기반 검색, 실시간 매칭, 운영 대시보드·경고. 세부 화면과 정보 구조는 담당 기능 명세에서 확정
- 후속 후보: 추가 조건 필터, 룰마스터 프로필·가능 게임, 후기
- 후속 후보: 온라인 방·플레이룸·외부 플랫폼 접근

## 8. 품질과 운영 요구사항

- 후속 온라인 기능의 접근 정보와 채팅은 현재 `ACTIVE` 참가자에게만 제공한다.
- P1 알림은 본인만 조회·읽음 처리하고, 알림 자체를 방 접근 권한으로 사용하지 않는다.
- P1 소셜 로그인은 제공자 subject를 정본 식별자로 사용하고 이메일만으로 기존 계정을 자동 병합하지 않으며 외부 token을 저장하지 않는다.
- P1 채팅은 로컬 프록시 뒤 애플리케이션 두 대와 공용 PostgreSQL·Redis로 교차 인스턴스 경로를 검증했다. AWS 검증 토폴로지와 배포·실측의 종료 상태는 [P1 기능별 종료 상태](archive/p1/README.md#기능별-종료-상태)의 `배포 상태`와 `실측 상태`를 따르며, 임시 검증 배포를 운영 배포로 해석하지 않는다.
- P2 운영 관측은 서비스 생존·지연·실패·AI 사용량·추정 비용과 핵심 업무 결과를 연결하되, 메트릭·로그 전송 ADR과 기능별 금지 데이터·label 계약을 구현 전에 확정한다.
- 여러 인스턴스에 등록되는 ROOM 상태 보정과 채팅 만료 삭제는 Spring Scheduler와 PostgreSQL ShedLock으로 한 실행만 소유하게 하고, 작업 본문은 재실행해도 같은 결과로 수렴시킨다.
- 다중 인스턴스에서도 ROOM·참가 정합성은 공용 PostgreSQL의 기존 낙관 락과 제한 재시도를 유지하며 Redis 분산 락으로 교체하지 않는다.
- 후기·참석·룰마스터 신뢰 정보는 역할과 근거를 분리해 저장하고, 공개 기준을 운영 정책으로 문서화한다.

## 9. 성공 지표

| 목표 | 지표 |
|---|---|
| P0 모임 성립 | 방 생성부터 모집 인원 충족까지 걸린 시간, 모집 인원 충족률 |
| P0 정합성 | 모집 인원 초과 차단 건수, 중복 참가 차단 건수, 상태 전이 오류 건수 |
| 탐색 전환 | 검색에서 방 상세·참가로 이어지는 비율 |
| P1 대기열 정합성 | 중복 활성 대기·중복 승격·누락 승격 건수, 대기 신청 뒤 승격·취소·만료·방 취소 결과 분포 |
| P1 알림 신뢰성 | 원인 이벤트 처리 지연, 미처리 이벤트 경과 시간, 재시도와 중복·누락 건수 |
| P1 채팅 신뢰성 | 메시지 저장 성공률, 인스턴스 간 저장 후 전달 지연, 신호 누락·중복·순서 역전과 재연결 복구, 권한 상실 뒤 차단 결과 |
| P1 ROOM 상태 처리 | 처리 후보·성공·실패·재시도 수, 미처리 ROOM 경과 시간, 스케줄 잠금 획득 결과와 실행별 데이터베이스 비용 |
| P1 ROOM 동시성 | 낙관적 락 충돌률, 요청별 재시도, 결과 분포, 응답시간과 데이터베이스 비용 |
| 모임 품질 | 참석률, 취소율, 후기, 재참여율 |
| 룰마스터 신뢰 | 룰마스터 진행 방 수, 후기 수, 재참가율 |
| 온라인 전환 | 온라인 방의 모집 인원 충족률, 플레이룸 활성화율 |

P2 기능은 구현 전에 상세 명세에서 지표의 공개 기준 정본, 최소 표본과 산식을 먼저 확정한 뒤 측정을 시작한다. 실제 측정값이 쌓이기 전에는 목표 수치를 추측하지 않으며, 자동 검증·임시 배포·`INVALID` 실행·운영 실측을 서로 대신하지 않는다.
