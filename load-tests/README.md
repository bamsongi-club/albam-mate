# Load Tests

이 디렉터리는 k6 부하테스트에 필요한 시나리오와 지원 소스를 도메인별로 관리한다. 도메인마다 fixture 준비 방식과 자동화 수준이 다를 수 있으므로 공통 경계만 정하고, 도메인 폴더 내부 구조는 담당자가 결정한다.

## 디렉터리 배치

각 도메인은 `load-tests/k6/<domain>/` 아래에 전용 폴더를 만든다.

```text
load-tests/
  k6/
    <domain>/
      README.md
      <scenario-and-support-sources>
```

도메인 폴더에는 k6 시나리오, 공통 모듈, fixture 생성기와 검증 테스트처럼 해당 부하테스트에 필요한 소스를 둘 수 있다. `tools/` 같은 하위 폴더의 이름이나 구조는 공통으로 강제하지 않는다.

## 용어

| 용어 | 의미 | Git 추적 |
| --- | --- | --- |
| k6 시나리오 스크립트 | k6가 HTTP·WebSocket 요청과 부하 profile을 실행하는 소스 | 추적한다 |
| fixture 생성기 소스 | 테스트 계정·도메인 데이터·적재 파일을 실행 시점에 만드는 소스 | 추적한다 |
| 생성기·설정 검증 테스트 | 생성기와 부하테스트 설정의 입력·출력 계약을 검증하는 테스트 소스 | 추적한다 |
| 가짜 예시 파일 | 입력 형식 설명이 필요할 때만 제공하는 비실행용 예시 | 실제 정보가 없을 때만 추적한다 |
| 실제 fixture | 부하테스트 환경에 적재하거나 로그인에 사용하는 계정·비밀번호·도메인 데이터 | 추적하지 않는다 |
| 생성 결과 | 생성된 fixture, 실행 bundle, 원시 로그와 원시 측정 결과 | 추적하지 않는다 |

fixture 생성기와 그 테스트는 재현 가능한 부하테스트를 위한 소스 코드다. 생성기가 실행하면서 만든 파일과 데이터를 실제 fixture 또는 생성 결과로 구분한다.

## Git 비추적 규칙

실제 fixture, 자격 증명과 생성 결과는 파일 확장자와 관계없이 Git에 커밋하지 않는다. JSON뿐 아니라 SQL, CSV, `.env`, 로그와 결과 파일에도 실제 계정·비밀번호·토큰·도메인 데이터가 포함될 수 있다.

생성 결과의 기본 경로는 `build/k6/<domain>/`이다. 저장소의 `.gitignore`가 `build/`를 제외하므로, 생성기와 실행기는 이 경로 안에서 도메인별 결과를 관리한다.

비밀값을 제거한 측정 증거를 정본으로 보존해야 한다면 `build/`의 원시 결과를 그대로 커밋하지 않고, 별도로 승인된 측정 문서의 형식과 검증 절차를 따른다.

가짜 예시 파일은 형식 설명에 필요할 때만 추가한다. 실제 서비스 계정, 접근 가능한 연락처, 재사용 가능한 비밀번호·토큰 또는 실제 환경의 리소스 식별자를 넣지 않는다.

## 도메인 README

각 `load-tests/k6/<domain>/` 폴더에는 `README.md`를 두고 다음 정보를 설명한다.

- 제공하는 부하테스트 시나리오
- 실행할 스크립트와 실제 실행 명령
- 필수 환경 변수와 사전 조건
- fixture 준비·정리 방법
- 결과 확인·검증 방법
- `build/k6/<domain>/` 아래에 생성되는 결과

문서의 제목 순서와 내부 구현 구조는 도메인 특성에 맞게 정한다.

## 파일명

시나리오와 지원 소스의 파일명은 역할이 드러나는 영문 소문자 kebab-case를 사용한다. `README.md`처럼 이름이 정해진 문서는 이 규칙에서 제외한다. 실행 순서를 표현할 필요가 있으면 숫자 접두사를 사용할 수 있지만 필수는 아니다.

숫자 접두사를 사용한다면 같은 도메인 폴더 안에서는 고유하게 관리한다. 서로 다른 도메인은 독립된 폴더를 사용하므로 같은 번호로 시작해도 된다.
